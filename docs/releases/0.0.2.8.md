## Overview

Large experiments can retain bounded exact-recovery history and periodic
improvement-only best-brain milestones while keeping every playback chunk,
metrics row and numbered run champion archive. The policies have independent
cadence and retention counts. No existing artifacts are migrated or deleted.

## Changes

- CLI recovery writes retain the latest successfully published files owned by
  this invocation, including final. A zero keep count disables pruning.
- Periodic warm-start exports require strict rank improvement and changed
  weights, with an optional absolute primary-score margin. The most recent K
  qualifying collections share a private weight pool. Publication leaves
  experiment/chaining state untouched; unreferenced newly owned periodic blobs
  are removed only after replacing the latest index.
- Explicit champion index paths are accepted by `--brains-from`, including the
  periodic `champions/steps/latest.json`. Directory selectors retain numbered
  run behavior; explicit indexes reject `--brain-run`.
- Optional shared binary v4 recovery files reference immutable configuration, action-order
  and signature blobs. Dynamic weights, optimizer/buffer/RNG/world state stay in
  each exact checkpoint. Standalone v3 output remains the default after measurement found no disk gain
  from cross-file metadata pooling in the bounded fixture.
- A fused native masked-PPO minibatch preserves sample order, masked logits,
  zeroed invalid-action derivatives, gradient accumulation, KL stopping and Adam
  cadence. Unsupported/legacy/customized paths retain their scalar fallback.

- Periodic gates and model publication share one byte-bounded, transaction-local
  encoding cache. Shared snapshots keep exact payloads/hashes across criteria;
  cache entries expire before another simulation step.
- Synchronous checkpoint writing borrows retained metadata rather than cloning
  model/config/report trees first. Public snapshots remain detached, controllers
  still stream one at a time, and old/new files decode identically.

## Compatibility and migration

Read [retention and portability](../artifact-retention.md). New readers retain
old JSON/compact/v3 support. Keep `_metadata/` with v4 files; older runtimes cannot
restore v4. Replay format, diagnostic cadence, simulation decisions and saved
brain signatures are unchanged. This is pending source work; the published
package version remains `0.0.2.0`. Rebuild native kernels to enable the new batch;
older native modules fall back without compiling during import.

## Validation

See the measured workloads and limitations in [performance](../performance.md#rolling-artifacts-and-masked-ppo-batches).
The regression suite covers exact masked training, rejection of malformed masks,
metadata checksums and continuation, publication failure preserving recovery,
changed-weight gates, bounded qualifying milestones, explicit-index loading,
and identical replay frames/final training state across retention policies.


- Python: 639 tests completed, 22 optional documentation-dependency skips, no failures.
- Viewer: all 123 JavaScript tests passed; seven source-rendered visual references verified.
- All 150 Python, four native source/header, 93 JS/CSS/HTML/JSON and two shell
  source files passed their formatter/check modes. Native kernels rebuilt on CPython 3.12.
- The pure-Python wheel built offline. An isolated installed-package smoke loaded
  29 bundled presets, ran five steps, restored its checkpoint and served viewer
  HTTP/catalog/chunk assets. No package was published.
- Three alternating fresh-process measurements per variant matched state hashes:
  13.1% less elapsed time for the 160-step training workload and 74.5% less
  retained checkpoint disk in the eight-save fixture. Optional metadata pooling
  was 372 bytes larger in that fixture, so it remains disabled by default.


Additional [encoding/copy measurements](../performance.md#shared-model-encoding-and-checkpoint-copy-reduction)
use three fresh processes per variant, matching seed 100 and exact state/replay
hashes. The 32-step complete workflow decreased from 4.047 s to 3.703 s (8.5%),
and process peak RSS from 118.64 to 99.23 MiB. Checkpoint/replay bytes were
identical. Periodic publication plus nine unchanged-weight checks decreased from
831.41 to 188.06 ms; metadata-preparation peak traced allocations decreased from
1,452,264 to 126,464 bytes. These are separate component and workflow measurements,
not additive improvements to the earlier masked-PPO figures.

The focused storage/encoding suite also passed 17 tests with `WTF_KERNELS=python`.
Public checkpoint mutation isolation, subclass metadata hooks, exact legacy and
binary file round trips, save-local reuse and bounded-cache eviction are covered.
