## Overview

Long multi-run training could continue after the monitored champions stopped
improving. Optional patience now stops after K consecutive completed training
runs without a selected champion rank improvement, with configurable species.

## Changes

- JSON `experiment.early_stopping.patience_runs` or CLI `--early-stop-runs K`;
  absent/zero disables the feature, preserving existing default run counts.
- Optional species list or repeated `--early-stop-species NAME`; omitted means
  all configured species. Any monitored species/sex improvement resets patience.
- Rank comparisons follow each group's selected champion criterion and existing
  tie-breakers. Other criteria, loss changes and weight/optimizer updates do not
  count. The monitor retains bounded rank metadata independently of publication
  and per-episode/best-so-far promotion settings.
- Fresh training establishes a baseline on the first completed run. Comparable
  known warm-start ranks seed a baseline before it. Only training consumes
  patience; evaluation/random execution preserves ordinary run limits.
- Stop only after a full run; save its replay, champions, metrics, summaries and
  final checkpoint. CLI output and `early_stopping.json` explain termination.
- Checkpoints retain best ranks, count and completion state. Both periodic-run
  and completed-stop resumes avoid phantom playback entries; a completed stop
  cannot silently start another episode.

## Compatibility and migration

No dependencies, precision, observation, policy update or replay codec changes.
Feature disabled by default; old checkpoints/configs remain valid. Existing
resume restrictions apply: change settings through a new experiment/warm start,
not CLI overrides on an exact checkpoint. This counter compares observed ranks,
not held-out frozen-policy quality. Varying worlds/opponents can affect progress.

## Validation

- Thirteen focused tests passed: patience boundaries, ties/regressions,
  any-group reset, species filters, custom names/sex-specific criteria, warm
  baselines, disabled/evaluation/random behavior, strict validation, cap limits
  and persistence. All nine algorithms pass exact binary continuation.
- Before stopping, world/RNG and brain checkpoints match an unmonitored control
  at every step (apart from the declared experiment setting).
- CLI checks confirm replay finalization, stopping-run archive/summary/final
  checkpoint, periodic checkpoint continuation and completed-stop resume.
- Full Python regression suite: 439 tests passed; seven HTTP socket cases
  excluded because this sandbox blocks localhost binding.
- All 50 JavaScript viewer tests passed. Ordinary completed-checkpoint resumes
  retain their existing one-frame final view.
