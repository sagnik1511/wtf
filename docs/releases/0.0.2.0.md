## Behavior

The former flat `ecosystem` import namespace becomes `wtf`. Simulation, learning,
experiment lifecycle, artifact storage, inspection and numeric/native support
have separate subpackages. The lazy public API exposes `Experiment` and
`load_config`; command entry points, installed resources and native build paths
use the new namespace. JavaScript playback remains independent of training.

## Migration and packaging

Update external imports using the [complete import map](../package-layout.md#migrate-existing-imports).
No old-namespace compatibility package is shipped. Reinstall local command
scripts and restart Python/viewer processes; rebuild optional native kernels as
`wtf.native._kernels`. Package discovery includes all `wtf` subpackages, the sdist
includes their native sources/headers, and a portable build excludes compiled
artifacts. Runtime assets remain allowlisted under `wtf/assets/`.

The distribution remains `wtf-wildlife-trial-framework`; its package version is
`0.0.2.0`, matching this rollout. This rollout does not publish, tag or rename the PyPI project. Artifact
formats, model signatures, RNG consumption, physics and viewer behavior are
unchanged; existing supported experiment files need no conversion.

  Isolated installations checked all 27 presets, CLI commands, short recording,
  checkpoint restore and viewer HTTP assets/catalog/chunks outside the checkout.
- The native and portable installed wheels also reproduced all pre-migration
  checkpoint/fresh-run hashes. No container or Ubuntu run is claimed by these
  local checks.
- Source formatting, configuration-reference validation and strict MkDocs/link
  checks passed. The complete directory and visual click-path catalogs include
  this migration guide and its light/dark package-boundary diagram.

## Rollback

Restore the prior source/package and command scripts together, then rebuild its
native extension. Preserve experiment directories. Do not combine modules or
compiled binaries from different layouts in the same Python process.
