## Overview

Per-episode winners could replace stronger starting models. Repeating decimal
weights and training configuration across champion JSON files also made a deep
river archive exceed 8 MB. Fresh experiments now retain best-so-far ranks, and
champion metadata references lossless, shared binary model snapshots.

## Changes

- `experiment.promote_only_improved` defaults to true. Independent species/sex/
  criterion records survive episode boundaries; candidates must beat the full
  existing rank tuple. Exact rank ties retain the incumbent snapshot.
- Matching typed warm starts seed their recorded criterion/rank. New worlds
  reset lineage counters while retained snapshots keep their original source.
  No opposite-sex model substitution or guessed legacy family rank is added.
- Next-run initialization uses the chosen retained champion, with the existing
  fresh private training state. `--no-chain-brains` preserves original-start
  initialization while archives continue tracking best-so-far records.
- Unchanged champions retain artifact identity/model generation. Per-run indexes
  remain available and mark retained entries with `improved: false`.
- Version-3 artifact JSON references SHA-256-addressed `champions/models/*.bin.xz`.
  The existing binary codec preserves exact FP32/legacy FP64 values, signed zero,
  signatures and parameter shapes. Shared weights are stored once, and repeated
  configurations are pooled within each numbered generation.
- Existing JSON artifact versions 1/2 still load. Library selection, run-number
  selection, moved experiments and shared-library localization support the new
  layout. No NumPy/PyTorch dependency or viewer format changes are needed.
- Full resume checkpoints retain their configured cadence and optimizer, buffer
  and RNG state. Their effective promotion flag and retained records persist.

## Compatibility and migration

New exports use version 3; old runtimes cannot load them. Keep the experiment's
shared models directory with its indexes and metadata. Old checkpoints without
an effective promotion flag preserve their prior behavior on exact resume;
new experiments/warm starts use the new default. Set the JSON flag false for
per-episode winner behavior. Restart training to use new code; existing active
processes and result folders are not modified or converted.

Rank retention changes cross-episode learning behavior intentionally. Recorded
rank improvement across varying seeds is not a frozen-policy evaluation or a
guarantee of generalization. Physics, arithmetic precision, observations and
playback codecs are unchanged.

## Validation

- Frozen first-run deep-river archive: 8,663,633 bytes before versus 620,497 bytes
  after, including the new index and shared pool (92.8% smaller). All 22 model
  values matched exactly; eight unique blobs used 521,548 bytes.
- An unchanged subsequent archive added 98,993 metadata/index bytes and zero new
  weight bytes. Raw local probe/results are ignored in `.cache/champion-storage/`.
- Nine focused promotion/storage tests cover strict/tied/independent records,
  warm starts, source removal, no-chain/legacy behavior, deduplication, checksum
  and path rejection, signed zero/FP64 and all-algorithm binary resume.
- Full Python regression suite: 426 tests passed; seven HTTP socket cases were
  excluded because this sandbox blocks localhost binding.
- All 50 JavaScript viewer tests passed.
- No training-throughput or peak-RAM improvement is claimed. No long training
  experiment or in-place conversion was run for this rollout.

## Rollout and rollback notes

Committed in `91697aa` on 2026-11-19. Reverting the promotion
flag restores per-episode selection for new experiments. Keep a new reader for
version-3 champions and promotion-aware exact checkpoints; do not edit metadata
to pretend binary references are inline legacy weights. Existing replay data
remains usable independently of champion storage.
