## Overview

Sparse same-step mutual choices make paired reproduction difficult to coordinate.
Opt-in consent persists while resting, allowing staggered reproduction choices
without widening the mating radius or bypassing the physical gates.

## Changes

- Adds `environments/mating_intent_ppo.json`: both species masked PPO,
  observation version 3, intent duration 5, mating radius 2. It inherits body,
  energy, reward and network settings from `maskable_ppo.json`, with the targeted
  prey-survival changes listed below.
- Reproduction grants a bounded per-animal consent. Rest preserves it; other
  actions, loss of eligibility, expiration and successful birth end its effect.
  Both parents must consent and pass all physical checks at the birth phase.
- Failed explicit attempts emit one `mating_failed` reason. Inspector displays
  remaining intent and last reason. Offline species/window analysis and telemetry
  expose counts by cause. Existing rewards, including failed-choice penalties,
  still apply; delayed parents receive their birth feedback at birth.
- Same-step reproduction-success ratios become unavailable for persistent intent,
  rather than presenting a misleading probability. Birth/attempt/reason counts remain.

## Configuration and compatibility

`intent_steps` accepts 1--128; omitted/default 1 preserves same-step consent.
Existing presets retain their reproduction timing and physical rules. New
failure events are observable even with legacy consent settings.

Two added animal fields are saved in JSON/binary checkpoints and replay field
tables. Old states default to no intent. Existing playback and model archive
formats remain supported. Version-3 inputs remain 42 values at k=1; inspector
intent/failure state is not appended to the neural input vector. The new preset
requires compatible version-3 masked PPO weights or a fresh run.

## Rollout and rollback notes

Use the new preset to opt in; existing presets stay at same-step consent.
Restart an already running viewer server to load updated Python readers and JS.
Use `intent_steps: 1` for new experiments to return to same-step consent.
Resume active checkpoints with this implementation: older code cannot restore
the added animal fields. These changes have no established ecological or speed
improvement until controlled experiments compare them with the prior rules.

## Prey survival and lineage follow-up

Updates survival-related settings in the same mating-intent preset:
prey sight 6→10, top-k 1→3, health 30→40 and movement energy cost 0.15→0.10.
The breeding health threshold rises 24→32, preserving the strict 80% gate.
Predator attack damage remains 30, so a single hit gives prey an escape
opportunity; multiple attacks remain lethal. No automatic escape is scripted.

Both species now chain lineage champions (age qualification 300/100 for
prey/predator) in separate sex pools. The existing lineage ranking, promotion
guard and other criteria remain. Input contracts become 66 for prey and remain
42 for predators; old prey models require a fresh start. Earlier results and
other environment presets retain their configurations. Radius remains 2 and
prey maturity/cooldown are unchanged. No claim of improved population stability
is made without a new comparison.

Follow-up validation: **66 targeted Python tests** (survival opportunities,
66-input training, lineage promotion/chaining, top-k invalidation, masks and
checkpointing) and **65 JavaScript tests** pass. Repository-wide format and
check modes pass over 104 Python, 4 native, 64 web/config and 1 shell sources.
The full Python HTTP suite was not repeated for this preset-only follow-up.
Documentation checks pass (112 Markdown files, 962 links, 53 SVGs).
