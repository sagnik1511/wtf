## Changes

The project includes the standard [MIT License](../../LICENSE), copyright
2026 Sagnik Roy, referenced by package metadata and included in the Docker
builder/runtime contexts.

A root installation guide covers isolated Python setup, optional native kernels,
Windows commands, Docker installation and a short smoke-run workflow. It links
this rollout and distinguishes source installation from unpublished PyPI/image
distribution.

A multi-stage Dockerfile and default-deny build context separate the native
compiler stage from the non-root runtime. Compose exposes independent training
and read-only playback services; a POSIX launcher maps user IDs and keeps results
in a host bind mount. The server gains an optional `--host` argument for container
binding while retaining its localhost default.

The compatibility policy distinguishes package releases, rollout versions,
checkpoint envelopes, brain artifacts and replay codecs. It describes current
reader capabilities and limits exact-continuation guarantees without inventing
a historical released-package support matrix.

A short Python example and a Markdown tutorial cover configuration, independent
training, chunked replay recording, champion export, readable metrics/analysis,
checkpoint restoration and offline playback. The tutorial includes the entire
runnable example; no notebook dependency or embedded outputs are required.

## Validation and adoption

Docker images/containers are intentionally not built or run. The launcher is
syntax-checked, and Python tests exercise the local example through recording,
champion export and exact-state loading into temporary output. They also check
tutorial/source consistency and opt-in server host parsing. Container build,
networking and volume smoke tests remain to be performed on a Docker host.

No artifact conversion or existing JSON change is required. Restart an existing
playback server only when the new bind-address option is needed. See the Docker
guide for build/run commands; the compatibility guide describes portable result
folders and native-versus-data portability. No PyPI publication is performed.

Three local workflow/parser/tutorial checks pass. Black (109 Python), clang-format
(4 native), Prettier (77 web/config plus Compose YAML) and shfmt (2 shell)
format/check modes pass. The launcher passes `sh -n`; documentation links and
whitespace checks pass. No Docker command was executed.

## Customization documentation

The customization handbook maps setup changes to JSON, CLI, viewer preferences
and source modules. Schema descriptions define every supported property, with a
generated complete field reference and a missing-definition/staleness check.
Separate command definitions, an executable two-prey species recipe and a
new-policy controller/integration guide cover common extensions. Contributor
context and agent instructions point future work to these contracts. The policy
class is an illustrative recipe, not a newly registered supported algorithm.

The generated reference covers 317 entries across all schema alternatives.
Documentation contract tests validate definition coverage, reference freshness,
all declared core CLI flags, the executable species recipe and the illustrative
policy class/checkpoint behavior. The schema changes add descriptions only;
validation constraints and supported runtime algorithm types remain unchanged.

The customization follow-up passes 24 targeted documentation/example/species
tests, full-reference regeneration, all formatter checks (111 Python, 4 native,
77 web/config and 2 shell files), local-link checks and whitespace validation.
Existing configuration-flow and private-learning visuals are reused in the
handbook rather than duplicating diagrams or adding experimental observations.
