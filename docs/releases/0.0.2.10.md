## Overview

Long training schedules can skip replay capture until their final K episodes.
`--record-last-episodes K` and optional `recording.record_last_episodes` default
to -1 (all); zero disables capture and positive K is capped at the scheduled total.
Skipped episodes never request frame snapshots/diagnostics or encode chunks.

## Changes

- Gate episode start and frame capture in the shared recorder, including direct
  Python callers; metrics, learning, champions and recovery retention are unchanged.
- Persist CLI selection in configuration/checkpoints and effective manifest settings.
- Keep original episode IDs, seeds, bounded chunks and normal viewer seeking.
- Preserve capture-disable precedence for training-only, enabled=false and no-record.
- Document that the window is scheduled, not a rolling early-stopped tail; resume
  records only remaining eligible frames and cannot backfill skipped history.

## Compatibility and migration

No replay/champion/checkpoint envelope change, file deletion or conversion.
Missing selectors retain all-episode behavior. Configurations/checkpoints that
explicitly contain the new property require current source; package 0.0.2.9 does
not support it. This rollout does not publish or bump the distribution version.

## Rollout and rollback

Opt in with `--recording-profile full --record-last-episodes 2`. Learning remains
active in these original training episodes. Use -1 to record all future episodes
or reset an inherited selector during inference. Existing recordings remain intact;
no model/checkpoint can reconstruct previously skipped training playback.
