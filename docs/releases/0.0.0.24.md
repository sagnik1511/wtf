## Overview

Shrinks replay and exact-checkpoint storage by writing structured binary data
rather than numeric text or base64-wrapped arrays. The renderer decodes binary
chunks directly, while metrics, summaries and champion artifacts stay readable.
The default compression prioritizes disk usage; existing formats remain readable.

## Changes

- Adds versioned `WTFB` records with raw float64 arrays, packed uint32 arrays,
  small-integer varints, dictionary strings and column-packed entity tables.
  Preserves signed zero, integer/float types and large Python RNG seeds.
- Streams binary replay headers, existing keyframe/delta packets and a validated
  frame-count footer. Each chunk remains independently seekable.
- Adds binary checkpoint version 3, streaming controller records and retaining
  shared metadata/models without base64. Public loading returns the existing
  version-1 in-memory state expected by the experiment restorer.
- Makes binary/XZ replay and `.bin.xz` checkpoints the CLI/preset defaults.
  LZMA2 dictionaries are limited to 1 MiB; gzip and uncompressed alternatives,
  compact JSON and plain JSON remain available.
- Adds JavaScript DataView decoding and binary HTTP negotiation. The server
  decompresses XZ one chunk at a time; older clients receive expanded JSON.
- Adds a verified `ecosystem.optimize_storage` converter for completed replay
  and checkpoint files. It publishes only smaller candidates after canonical
  state/frame verification and source-change checks. Active runs are refused.
- Avoids constructing static world fields for each recorded frame. Adds a locked,
  stat-validated LRU of four detached telemetry pages and avoids repeated
  manifest reads while assembling each page.
- Documents storage behavior and migration in the [binary storage guide](../binary-storage.md).

## Compatibility and migration

No tensor-library or browser-package dependency is added. Training mathematics,
model signatures, rewards, reproduction, seeds and recording cadence are unchanged.
Raw float64 values are preserved; this is not model quantization or dropped replay
frames/diagnostics. CSV metrics, JSON summaries and champion weights are unchanged.

Restart Python/viewer processes to adopt the new reader/writer. Current readers
accept old snapshot/delta JSON and gzip data, including mixed formats after
interrupted conversion. Legacy checkpoint paths resolve converted binary copies
when the original is absent. Older runtime versions cannot load binary checkpoints;
retain a compatible reader when rolling back. XZ prioritizes disk size and can use
more CPU than gzip; the 1 MiB dictionary is not a bound on total encoder memory.

Use `python -m ecosystem.optimize_storage results/EXPERIMENT` for both replay and
checkpoint conversion. The guide includes batch, restricted and gzip alternatives.
Verification is per file, not an all-experiment transaction. Failures keep that
file's originals, and previously completed conversions stay readable.

## Validation

Passed **265 Python tests** and **31 JavaScript tests**, viewer module syntax,
local link checks and Git whitespace checks. Added tests cover typed arrays and
columns, large seeds, signed zero, corruption/truncation rejection, Python/JS
parity, playback seeking, all-algorithm binary checkpoint continuation, training
transparency, failed conversion preservation, smaller-original retention,
legacy HTTP clients and bounded/file-validated telemetry caching.

Converted the completed 20-episode local A2C experiment

chunks passed the JavaScript decoder, and the converted final checkpoint restored
all 20 completed episodes. These measurements describe one experiment and no
speed or peak-memory improvement is claimed. Generated results remain ignored.

## Rollout and rollback notes

New runs use the updated defaults. Existing recordings are changed only by the
explicit converter; existing training configurations are not retuned by conversion.
For smaller compression CPU costs choose replay `compression: "gzip"`, or write
`.bin.gz` checkpoints programmatically. `--checkpoint-format compact` retains the
older compact JSON/gzip format and `json` retains plain JSON.
