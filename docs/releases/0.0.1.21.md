## Overview

Generated local experiment output and common developer/build artifacts should
stay out of future commits while maintained code, documentation media and
the manuscript workspace remains local and outside package tracking.

## Changes

- Expands root ignore rules for Python/package builds, native intermediate files,
  dependency installs, test/coverage/profiling caches, local environment files,
  logs and OS/editor temporary files. Sanitized `.env` examples remain trackable.
- Ignores `docs/experiments/`, the raw working-output directory used by the matrix
  harness. The existing untracked raw matrix files total approximately 16 MiB.
  The entire `docs/paper/` workspace is also ignored, including manuscript sources
  and evidence. Index-only removal keeps every local file intact.
- Adds missing LaTeX bibliography, table-of-contents and auxiliary-file rules to
  the paper-local ignore file. These local rules are subordinate to the full
  workspace exclusion; intentional package documentation media remain tracked.
- Documents tracked-versus-ignored auditing and targeted index-only removal.

## Compatibility and validation

No simulation, viewer or stored artifact format changes. The initial audit found
no tracked caches or runtime artifacts. The manuscript workspace is explicitly
removed from the Git index while retaining local files. Package-documentation
links into that optional workspace are removed. Ignore checks and documentation
links are validated, and unrelated index entries remain unchanged. No commit or
history rewrite is performed.

## Rollback

Revert the relevant ignore entries to make local outputs visible to Git again.
Nothing needs to be restored from disk. These rules prevent future additions;
they do not remove files from historical commits or shrink local results.

## Local manuscript ownership

The top-level workspace exclusion takes precedence over its local source-data
keep list. Source/evidence organization remains useful locally but is no longer
a commitment to include manuscript files in Git. Existing history is retained;
the removal affects the next committed tree only.

## Documentation ownership

Separates reusable package guidance from manuscript observation history. General
guides and workflow instructions exclude trial logs and run identifiers; current
calibration recommendations retain their supported scope and tradeoffs. Release
records cover implementation/configuration changes and their checks rather than
experiment execution. This is documentation maintenance, not a new runtime release.

## Shared repository boundary

Excludes local manuscript/study runners, exploratory experiment-only tests and
study-only artifacts through explicit rules. The legacy hunting scratch script
and historical calibration-study diagram are removed from the index while local
copies remain. The public diagram manifest excludes the local study artifact.
A local manuscript-tooling note is removed from package release navigation.
Build/calibration/benchmark tools, runtime tests, presets, skills and intentional
documentation media remain available for tracking. No runtime defaults change.

An isolated copy containing only public package/configuration/test files collects
the maintained Python suite without local research dependencies. Targeted
reproduction, mutation and escape tests pass there. Public Markdown links are
checked for dependencies on ignored paths; source formatters and check modes pass.
