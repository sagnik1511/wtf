## Overview

The combined all-species movement heatmap stays in the viewer sidebar, reached
by the All-species heatmap shortcut. Metrics dashboard shows a compact heatmap
beside every species' metrics. Selecting an exact species enlarges that group,
including extinct species. Species cards share a count color scale for direct
comparison. Heat accumulates from the first saved frame through the current
playback step, independently of the trend History window.

Local witnesses, general consequences and context consequences use consistent
SVG dimensions, label/outcome columns and row spacing. Wide dashboard groups
align in columns; narrower inspector groups stack with proportional sizing.
Independent action labels and evidence semantics are preserved.

The population/food overview is also inside Metrics dashboard, open by default.
It keeps all configured species and the separate food axis, using the existing
bounded run history through the playhead. Dashboard Species/History filters affect
the per-species views; the overview retains its independent run scope. Resizing,
opening the dialog and theme changes repaint the existing canvas. Current board
totals remain visible.

## Changes and compatibility

One reusable Uint32 grid per configured species plus the combined grid is updated
in one replay pass with shared previous positions. Filter changes reuse these
grids immediately without replay reads or pausing. Distant seeks stream one
prefix with `by_species=1`, returning every group together; no extra replay
artifact, per-frame grid archive or whole-run browser decode is added. Prefix
validation checks all groups before modifying any grid. Count storage is
`4 × width × height × (species count + 1)` bytes, excluding canvas pixels and
metadata. This deliberately uses more current-grid memory to support side-by-side
comparison without retaining a history of grids.

Existing recordings work without conversion. Simulation, learning, stored values
and viewer seeking semantics are unchanged. Restart an existing playback server
after updating, so its Python movement endpoint matches the new viewer.

## Fixes and optimizations

Independent review verified and reproduced the playback-boundary fixes. Backward
seeks immediately remove future telemetry while older history loads. Failed
cross-chunk seeks reject incoherent snapshots, and failed run-metrics loads
invalidate the old chunk before it can be relabeled as a new run. Passive redraws
retain committed state during an incomplete seek. Sidebar movement painting,
including theme changes, waits for the committed frame, tick, run and group
container; it cannot paint a pending frame or another recording's grid.

Species cards and legends reuse bounded exact-name node caches within one
recording/run, refresh current values/colors and reset at run changes. Repeated
chart choices share series only during one draw, hidden compact heatmaps defer
painting until visible again, and direct chart-bound/position-map loops avoid
staging arrays and large spread calls. Three-species/1,000-redraw evidence reduces
DOM constructions from 62,105 to 143 and child replacements from 3,002 to 10,
with matching per-draw DOM snapshots. These are harness operation counts, not
measured whole-viewer speedups or peak-RAM reductions. Grouped movement keeps
shared prior positions, one replay pass and current count buffers only; no
per-frame grid archive, simulation change or additional replay artifact is added.
