## Overview

Linux/NVIDIA users can explicitly build and select CUDA kernels while the CPU
backend remains the default. The prototype batches independent dense action
networks across eleven learner families and DQN/DDQN gradient jobs. It does not
move every learner's optimizer/backpropagation to the GPU.

## Changes

- Explicit NVCC build and versioned ctypes ABI without mandatory Torch/CuPy/NumPy.
- Batched dense forwards for PPO, masked PPO, A2C, REINFORCE, GRPO, MAPPO,
  TRPO, discrete SAC, QR-DQN, DQN and DDQN; mixed unsupported brains remain CPU.
- Independent DQN/DDQN TD-target, Huber and gradient computation, followed by
  existing CPU clipping/Adam/target synchronization before inheritance/selection.
- Bounded, mode-specific workspace LRU and synchronous checkpoint boundaries.
- Real-device opt-in tests and a full-loop, isolated CPU/GPU benchmark covering
  initialization, packing/transfers, updates, world work and process RSS.

## Compatibility and migration

CPU remains unchanged by default. Model/checkpoint/replay formats stay portable;
backend handles are never serialized. Restore defaults to CPU and CUDA must be
selected explicitly again. The viewer is unchanged. GPU double arithmetic may
round differently from CPU sums/math; CUDA trajectories are not guaranteed
bitwise-identical. Recurrent/legacy/custom controllers remain CPU-only. CUDA
source ships with portable builds, but device-local shared libraries do not.
No package publication or package-version bump is included.

## Fixes and optimizations

Independent `wtf-reviewer` review corrected benchmark world randomization so
CPU/CUDA cases use the requested matched seed and record the actual seed. Custom
`_predict` overrides now retain the CPU path. Real-device validation compares raw
gradients/loss before Adam across multiple hidden layers and terminal/truncated
samples, preventing Adam normalization from hiding gradient-scale defects.
Regressions cover all eleven benchmark learners and instance/class hooks.

Batched private dense forwards/TD jobs and bounded, mode-specific workspace reuse
are implemented. No NVIDIA speedup or GPU-memory measurement is verified locally.
Policy backpropagation/optimizers, GRPO trial evaluation and world physics remain
CPU-side. The [guide](../cuda.md) specifies required Linux/NVIDIA validation.

## Rollout and rollback notes

Build on the target Linux/NVIDIA machine, require `WTF_TEST_CUDA=1` tests to pass,
and benchmark complete loops before adopting. Return to `--device cpu` to disable
this backend. Existing playbacks and portable model/checkpoint state are retained.
