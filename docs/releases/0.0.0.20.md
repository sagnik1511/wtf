## Overview

Adds a separate PPO environment for testing a larger predator model while
keeping the prey model small. Both species pass their longest-lived champion
to the next episode, so fresh initialization and survival-based inheritance
can be used together.

## Changes

- Adds [ppo_large_predator.json](../../environments/ppo_large_predator.json):
  prey retain one 16-unit hidden layer; predators use two layers of 64 and 32
  units. Both use tanh, five policy outputs and a value output.
- Predator parameter count increases from 438 to 3,622 per animal, including
  biases and the value output. Prey retain 438 parameters.
- Explicitly sets `champion_selection.criterion` to `lifespan` for both species.
  The standard [ppo.json](../../environments/ppo.json) remains available with
  its existing prey-lifespan and predator-kills defaults.
- Preserves the baseline world, body, rewards, reproduction and PPO training
  settings, including the predator learning-rate multiplier of 1.25.
- Documents fresh starts, cross-episode selection and architecture compatibility
  in the [configuration guide](../configuration.md#larger-predator-ppo-network).
- Reconciles the preceding documentation rollout with its existing commit and
  links this pending rollout from the release hub.

## Compatibility and migration

This rollout uses existing network and champion-selection support; it adds no
runtime algorithm, dependency, schema, checkpoint or replay-format changes.
New experiments must explicitly choose the new environment JSON.

Fresh weights and winner selection are separate controls. `--brain prey=fresh`
and `--brain predator=fresh` clear initial saved-model requests. The JSON's
lifespan criteria then govern subsequent episodes when chaining is enabled.
Lifespan ranks individual age, including individuals that died during an
episode; it does not require the champion to be alive at episode end.

Old single-layer predator weights cannot initialize the larger architecture.
Use fresh predator weights or a compatible `[64, 32]` predator champion. Loading
compatible weights with `--brains-from` is a warm start, not an exact optimizer
resume. An explicit CLI champion criterion can override the JSON criterion;
see the [saved-brain guide](../brain-library.md#choose-models-with-cli-arguments).

The larger model requires more parameter and optimizer storage per predator
and more computation per decision and training update. No timing or memory
benchmark is claimed. More parameters do not guarantee better learned behavior.

- Validated the new preset with `ecosystem.config.validate` and confirmed both
  species resolve to lifespan selection through the existing selector.
- Constructed both PPO networks and checked their output dimensions and
  parameter counts: prey 438; predator 3,622.
- Inspected a completed local 20-episode experiment on seeds 100–119: it started
  without saved brains, recorded the expected architectures and lifespan
  criteria, and chained episode 19's lifespan champions into episode 20.
  This verifies the configured workflow; it is not a controlled learning-quality
  or performance benchmark. Generated results remain outside the release docs.
- Checked local Markdown links, consecutive rollout numbering, the preceding
  commit association and Git diff whitespace. No new runtime implementation
  was introduced, so the full runtime test suite was not rerun for these docs.

## Rollout and rollback notes

Use the fresh-start command in the configuration guide from the project root.
Existing experiments keep their recorded configurations. To reproduce the
standard smaller-network setup, select `environments/ppo.json` in a new
experiment; to retain the larger network with kill selection, set the predator
criterion to `kills` in a separate environment configuration. Preserve compatible
brain archives before switching architectures.
