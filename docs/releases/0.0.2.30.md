## Overview

FP32 DQN/DDQN gradient publication spent substantial host time widening individual
values before CPU Adam. The comparison path now widens a whole packed array in
one native loop. The CUDA optimizer path keeps gradients, clipping, Adam and target
synchronization on the GPU, with coherent CPU snapshots at every grouped update.

## Changes

- Add exact optional native FP32-to-FP64 gradient conversion with reusable staging.
- Avoid allocating CPU gradient trees for deferred DQN updates.
- Add DQN/DDQN device Adam and scheduled target updates, retaining private state,
  replay sampling, RNG ownership, grouping safeguards and update counters.
- Cache online/target/Adam contents within bounded workspaces; invalidate after
  changes, slot reuse, eviction or failed native publication.
- Publish CPU weights/moments/variances and loss summaries before selection,
  inheritance, diagnostics and checkpoints. GPU execution never changes readers.
- Expose transient `--cuda-optimizer cpu/cuda`, default cuda when CUDA is selected.
- Prefer Linux `/proc/self/status` VmHWM for benchmark host peaks to avoid inherited
  process-rusage floors in notebook-launched workers.
- Update adaptive architecture diagrams and CPU/GPU comparison instructions.

## Compatibility and migration

Rebuild both optional native CPU and CUDA extensions. CUDA ABI 3 explicitly rejects
older shared libraries. Old CPU extensions without the widening helper retain their
conversion fallback. CPU remains the default; artifact formats, simulation physics,
viewer behavior and saved-model contracts are unchanged. Device clipping/Adam use
double arithmetic and FP32 storage; optional FP32 forward/backward remains configurable.
CUDA rounding can differ from earlier device/CPU execution; bit-identical GPU
trajectories are not guaranteed. Restored checkpoints start on CPU and need explicit
CUDA selection. No package-version bump or publication is performed.

## Fixes and optimizations

Independent `wtf-reviewer` inspection found no further actionable defects in the
reviewed runtime scope. Verified safeguards include grouping by optimizer settings,
private update counters and target cadence, exact-content invalidation after slot
changes/host edits, failure cache invalidation, and publication before champion
selection, offspring inheritance and checkpoint reads. Deferred updates omit unused
CPU gradient trees while the ordinary CPU allocation/sampling order is preserved.

The optional bulk widening helper preserves gradient bytes exactly and validates
buffer widths/types before writing. The developer's 64-model host unpacking
measurement was 15.295 ms → 0.455 ms (33.6×); an independent repeat measured
16.489 ms → 0.557 ms (29.6×), also byte-identical. These are isolated host-path
measurements, not full-loop GPU speedups. Linux benchmark host peaks now prefer
post-exec VmHWM rather than inherited rusage history.

Changed-file Pylint 4.1.4 passed with exit zero. The independent targeted suite
completed 70 tests successfully, with five explicit NVIDIA tests skipped. Existing
narrow argument/complexity suppressions keep ABI/state-publication operations
inspectable; no blanket suppressions were introduced. No additional fixes or owner
decisions remain from this review. CUDA compilation, resident optimizer execution,
numerical comparisons and speed/memory measurements still require Colab/NVIDIA.
