## Overview

Individual lifespan and hunting records do not capture whether an animal's
family survives and reproduces across biological generations. Training now
archives a species/sex-specific `lineage` champion alongside all existing
health, kills, lifespan, food and predator-balanced modes. Defaults are retained.

## Changes

- An incremental founder-family ledger tracks unique descendants across both
  parents, preserving dead relatives' counters without their brains. A candidate
  uses its strongest ancestral founder family; overlapping families are never
  summed into a duplicated score.
- Candidates must reach the selection age and personally hunt/feed to earn a
  birth-generation advantage. Then predators rank by family kills and prey by
  family animal-time, with viable descendants and further family/personal
  tie-breakers. Unproven pools retain explicitly marked provisional snapshots.
- `--champion SPECIES[:SEX]=CRITERION` chooses later-run curation without
  requesting saved initial weights. JSON, existing `--brain` run selectors and
  shared-library selectors accept `lineage` as well.
- Champion artifacts expose family totals, normalized rates, qualification and
  scoring policy. New exact checkpoints retain a compact per-animal ledger and
  aggregate counters, preserving floating-point accumulation on resume.
- Family membership is cached at birth and updates use individual counter
  deltas. No repeated recursive pedigree walk or retained deceased network is
  needed. Only one additional model per present species/sex pool is archived.

## Compatibility and migration

Actions, rewards, observations, inheritance, mutation, native kernels and replay
formats are unchanged. Champion snapshots are observed records at their saved
step, not a retrospective search through all discarded controllers. Family
statistics are metadata; the viewer still reads its existing replay chunks.

Model generation increments and warm starts do not count as births. Each new
episode resets physical ancestry even when weights chain between episodes.
Existing criteria remain available and existing default selection is unchanged.
Legacy checkpoints without the ledger continue with partial-history markers;
unavailable ancestors are not invented. Old champion-only archives cannot be
reconstructed as lineage winners. Explicit lineage loading from such an archive
fails clearly. Older application revisions do not understand the new criterion;
retain this reader when resuming checkpoints that use it.

Shared-library lineage ranking requires matching policy/signature/species/sex;
explicit run/path warm starts still transfer compatible weights into the new
environment without copying its physical ancestry. See the selection guide for
the exact rank, age override and fresh/chained/saved-model commands.

## Validation

All **395 Python tests** passed in the regression suite excluding seven
localhost-socket tests, which cannot bind in this sandbox. All **50 JavaScript
viewer tests** passed. The **nine dedicated lineage tests** also passed with
`WTF_KERNELS=python`, covering duplicate ancestry, deceased relatives,
maturity/personal-effort gates, arbitrary species names, sex-specific pools,
chaining across all nine algorithms, archive selectors, exact fractional-counter
continuation and legacy boundaries. A CLI test verifies fresh initialization
and two-run lineage chaining. Existing archive-count expectations now include
the additional lineage models; snapshot-copy equivalence checks still pass.

Black checks passed for all ten affected Python files, Git's whitespace check
passed, and 151 local links resolved across affected documentation. No training
performance or long-term ecological improvement is claimed by these checks.

## Rollout and rollback notes

Opt in with `--champion prey=lineage --champion predator=lineage`, or a species
`champion_selection` setting. Select an existing criterion to return to previous
curation behavior; historical lineage models remain available. Extra model
artifacts and checkpoint counters consume some disk space, without increasing
replay frame size. No server restart, package install, model-architecture change,
commit, tag or package-version bump is required. The preceding geography record
is reconciled with verified commit `d320059`.
