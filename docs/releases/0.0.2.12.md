## Overview

Checkpoint metadata encoding no longer serializes and hashes the same shared
container at every occurrence. Native PPO updates prepare their immutable sample
rows once rather than rebuilding them each epoch. Learning order, world state,
random streams and playback contents remain unchanged.

## Changes

- Add a metadata-traversal identity LRU bounded to 128 strong references. Clear
  it on success or failure before consuming streamed controller states. Public
  encoder calls remain mutation-sensitive; separate equal values still deduplicate
  by content, and optional external metadata pooling keeps its existing path.
- Prepare native PPO sample tuples once per update, including observation/mask
  slices for masked PPO. Minibatches gather references in the original shuffled
  order. Scalar/customized paths do not allocate this scratch list. Samples are
  not persistent state; retaining them until update completion trades some peak
  allocation for less repeated preparation.
- Document bounded cache ownership in the checkpoint structure figure and guide.
  Provide a reproducible fresh-process benchmark with state, restore and replay checks.

## Compatibility and migration

No schema, checkpoint version, model signature or replay format changes. All
playback files and configured retention policies are preserved. Public snapshots
and restored controllers remain detached; numerical precision, optimizer cadence,
KL stopping and RNG consumption stay unchanged. No kernel rebuild or viewer
update is required. Package version and published distributions are unchanged.

## Validation

Regression tests cover repeated/equal metadata, eviction, cleanup after failure,
new-save mutation, streamed iterator mutation and detached decoding. PPO tests
check sample packing, reuse across epochs/resume and absence of preparation in
the fallback path. Existing native/scalar parity tests remain in place.
See [performance](../performance.md#checkpoint-metadata-cache-and-ppo-sample-preparation)
for exact benchmark scope, measurements and memory tradeoffs.

Full Python discovery passes (670 checks, 22 optional skips), alongside all
124 JavaScript tests. The benchmark matches encoded metadata, complete model/RNG
state, byte-identical workflow checkpoints, exact restore and decoded playback.
Five-sample medians show metadata encoding 706.57→225.96 ms and the short complete
workflow 1.844→1.772 s. Update-only differences are modest; masked sample retention
increases peak Python allocation, as detailed in the linked performance guide.

## Rollout and rollback

Use current source; there are no new configuration switches. Reverting these two
internal optimizations preserves artifact readability and requires no migration.
