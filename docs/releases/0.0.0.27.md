## Problem and behavior

An older playback process could list newly written experiments while returning
404 for existing binary chunks. It retained older Python readers but served
updated viewer files from disk. Restarting the playback process restores access.

The server now advertises `X-WTF-Replay-Protocol: binary-v1`. The viewer checks
binary metadata and chunk errors and gives explicit restart instructions when
the capability is absent. Genuine missing chunks on a current server retain
their original error. Legacy JSON recordings remain supported without the header.
The request/decoder logic lives in `viewer/api.mjs` for direct testing.

## Compatibility and rollback

No recording, checkpoint, configuration or simulation format changes. Restart
`./run.sh` and refresh the browser to adopt this change; existing results require
no migration. Reverting the reader diagnostic restores the less specific error.
See [playback troubleshooting](../running.md#start-playback).

## Validation

- Seven API regression tests cover capability checks, converted metadata,
  legacy JSON, genuine missing chunks and binary request negotiation.
- All 38 JavaScript tests and 20 Python binary-storage/server tests pass.
- Live saved binary recording opens, seeks across chunks and selects another
  run through the actual HTTP API and JavaScript Playback engine.
