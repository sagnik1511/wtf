## Overview

Removes repeated network passes and temporary allocations from the GRU,
QR-DQN, MAPPO and masked GRPO trial paths. The shared MLP supports returning
input derivatives during its existing backward pass and evaluating a selected
range of output heads. Algorithm settings and simulation semantics remain intact.

## Changes

- Fuses GRU output-head input and parameter derivatives into one backward pass.
  Value bootstrapping skips unused policy outputs, and gate dot products use
  native multiplication iterators while retaining summation order.
- Reuses one QR-DQN prediction for diagnostic means and quantiles. Target
  inference evaluates only the next action's selected quantile heads, while
  the online selector still evaluates every action.
- Reuses MAPPO's post-step critic context instead of rebuilding it for the next
  decision. Pure MAPPO phases skip unused action-mask occupancy maps, and greedy
  execution evaluates only the actor.
- Builds each PPO variant's actual network directly, avoiding discarded default
  networks and, for GRU/MAPPO, their temporary optimizer arrays.
- Shares one occupancy map per GRPO trial step across masked agents and computes
  their frozen policies without shallow controller copies.
- Adds operation-count/numerical regression checks and updates the
  [performance guide](../performance.md#additional-algorithm-review).
- Reconciles the preceding reproduction-window rollout with its actual commit.

## Compatibility and migration

No environment, action, reward, model size, update schedule, buffer capacity,
checkpoint, replay or champion-signature changes are required. Existing warm
starts and exact checkpoints continue through the same interfaces. Internal
network factories and optional MLP output-range/input-gradient operations support
the reductions without adding per-animal caches or package dependencies.

## Validation

Passed **251 Python tests**. Added regressions cover direct construction,
combined input/parameter gradients, value-only recurrent bootstrap, selected
output ranges, one-pass QR-DQN diagnostics, one post-step MAPPO context, actor-only
greedy execution and shared masked-trial occupancy without controller copies.
The existing advanced-algorithm suite still checks finite differences, exact
plain/compact resume, births/deaths, champion chaining and CLI workflows.

Exact serialized state matched revision `0ae8df0` in **230 comparisons**:
23 per case across nine algorithms plus mixed GRPO/Maskable PPO, using two
11-step episodes and a completed-lifecycle check. The workload includes
reproduction windows, champion chaining, forced mortality in the nine-algorithm
cases and restoration in the mixed case. States include optimizer, RNG,
experience, world and champion data. These are correctness checks, not timing
measurements. No profiling or speed/peak-memory benchmark was performed.

## Rollout and rollback notes

Start a new Python training process to adopt the changes; an already running
process keeps its imported implementation. Existing environment JSON and saved
brains can be reused. No new viewer implementation or recording format is
introduced. Reverting the associated source changes restores the former
computation paths without converting experiment data.

Keep this rollout Pending until committed, then record its actual hash/date in
the child and hub. No Git tag, commit, package-version change or publication is
created by preparing these notes.
