## Result

The previous two-valley map scattered both diets everywhere. Enclosed valleys
now has one elevated walled interior with two three-cell-wide gates, guarded approaches
and an exterior river/ford. All 48 founding prey start inside; all 12 founding
predators start outside. Of 80 food patches, 30 start within two cells of the
inner boundary, 30 near the outer boundary and 20 farther away.

Adds optional top-level `placement`, validated in Python and JSON schema, with
rectangle bounds, exact species-name zone choices and food fractions/band width.
Insufficient dry zone capacity is an error. Shared zones avoid founder overlap;
food can overlap founders as before. See [layout configuration](../geography.md#enclosed-valley-starting-layout).

Placement is an initial-condition rule. Movement through gates and local births
remain normal. The enclosed-valley preset now uses DQN for prey and the existing small terrain
PPO template for predators. Radius-two mating, health/energy
constants, observations (32 inputs) and actions remain unchanged. Prey retain the compatible terrain Q/DQN signature; predators now require
terrain PPO weights rather than previous Q champions. Other configs
omit placement and retain their original layout RNG sequence. No new dependency.

  PPO.

  used the captured previous geometry and do not predict this new scenario.

## Adoption and compatibility

Use the existing `environments/enclosed_valleys.json` command in a new invocation.
Saved results/checkpoints keep their embedded map and initial state; resuming
never relocates animals. Existing viewers render ordinary obstacles/elevations
and food without new frame fields or codec changes. Keep the updated engine for
new checkpoint configs containing `placement`; older strict validators reject it.
Compatible terrain DQN prey and PPO predator champions can load, though the
spatial distribution changed. Use fresh predator brains when starting from
earlier Q champions.

Rollback requires both the prior map/config and the corresponding engine as
needed, preserving saved data separately. No commits, tags or package versions
were created by preparing this rollout.
