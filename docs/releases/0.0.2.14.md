## Overview

The LSTM cell's gate/parameter loops now have optional compiled forward and
backward paths. Independent hidden/cell state, PPO updates, RNG consumption,
simulation physics and viewer artifacts retain their previous semantics.

## Changes

- Add feature-detected `lstm_step` and `lstm_backward` under existing native API v2.
- Preserve four-gate order, compensated reductions, libm squaring, FP64 memory/
  gradients and existing FP32 parameter storage. No reordered/FMA arithmetic.
- Keep call-local vector workspaces and borrowed parameter buffers; validate all
  cell gradient buffers before modifying them. No cache enters a saved artifact.
- Keep the MLP head and optimizer interfaces unchanged. Missing symbols and legacy
  list/FP64 parameters retain Python execution without a compiler requirement.
- Provide a fresh-process before/after benchmark with complete state, exact
  restore, checkpoint-byte and replay-byte/decoded-frame comparisons.

## Compatibility and migration

Rebuild with `python -m work.build_native` and restart the trainer to enable the
new entry points. Existing processes retain their mapped extension. There is no
model signature, replay/checkpoint format, preset, JS viewer or package-version
change. The preceding LSTM-capable source can read the same artifacts. Old
published runtimes that do not implement `lstm_ppo` remain incompatible with
that policy, independently of this kernel change. Python fallback remains.

## Validation and measurements

Exact tests cover forward/tape/value-only paths, nonzero hidden/cell memory,
saturated gates, nonzero gradient accumulation, recurrent sizes 1–128, malformed
inputs/buffers without partial cell-gradient mutation, missing symbols and FP64
fallback. Controller/world checks include pending decisions, terminal/truncated
resets, private RNGs, optimizer continuation, diagnostics, multiple recorded runs,
chunk boundaries and checkpoint restoration. Existing birth/mutation coverage
also runs the native LSTM path.

Five alternating fresh-process medians compare the preceding native-enabled
package with the extension: 500 forward calls 316.63→11.18 ms, 500 backward calls
466.01→6.42 ms, eight rollout updates 815.86→25.32 ms and the bounded complete
workflow 8.154→2.323 s (3.51×). Final state, checkpoint bytes and replay bytes
match. Disk size is unchanged. See the linked performance section for full
workload definitions, traced allocation increases, RSS scope and limitations.

Final native-enabled discovery passes 689 Python tests (22 optional documentation
skips), all 125 JavaScript tests and 27 explicit documentation/source checks.
The Python-only selection passes 48 targeted checks with seven native-only tests
skipped. Black checks 163 Python files, clang-format four native files, Prettier
93 web/JSON files and shfmt two shell files. Kernel rebuild and configuration
reference validation pass. All numeric and playback equality checks are exact.

## Rollout and rollback

No runtime configuration migration is necessary. Removing the extension or
selecting `WTF_KERNELS=python` restores reference execution. No recordings,
champions or checkpoints are converted, pruned or rewritten by this change.
