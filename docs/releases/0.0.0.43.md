## Behavior and implementation

An optional CPython C extension accelerates dense-layer forward/backward passes,
chosen-action DQN gradients, SGD and clipped Adam. Shared layers benefit all nine
algorithms; recurrent PPO gains head/optimizer acceleration while GRU cell loops
stay in Python, and QR-DQN retains its Python pairwise quantile objective.
Environment/visibility logic remains Python. Each controller owns its buffers
and RNGs; kernels retain no global scratch or random state.

Build explicitly with `.venv/bin/python -m work.build_native`. New training
processes automatically use a compatible local extension when available;
`WTF_KERNELS=python` selects the reference and `WTF_KERNELS=native` requires the
extension. No compilation occurs during imports. Binaries, build files, source
snapshots and raw benchmarks are ignored. No ML framework/Cython dependency,
commit, tag or package-version change is introduced.

Float32 parameter/moment/variance storage keeps the preceding rollout's rounding
boundaries; arithmetic and native scratch gradients use doubles. C compilation
disables fast-math, FMA contraction and builtin-pow substitution. Bias is added
after ordered products, and stored rounded moments feed the Adam update. The
Python fallback keeps its original scratch-list representation. Legacy float64
brains use Python; CPython 3.12+ also falls back because its float summation differs.
The native backend currently supports CPython 3.9–3.11 with Clang/GCC toolchains.

## Validation and performance

See [CPU kernels](../native-kernels.md) for setup, coverage, regression checks and
benchmark results. Benchmarks compare unchanged full-population presets with
seed 42 and one 180-step episode, using median wall times of three separate
processes. An ignored copy of the staged pre-kernel FP32 sources supplies the
original baseline. Complete-state SHA-256 comparisons include learned weights,
optimizer state, buffers, RNGs, world, metrics and champions. Initialization and
semantic-digest construction are outside the reported training-loop time.
The terrain recording case includes normal binary/XZ recording costs.

The completed [benchmark table](../native-kernels.md#benchmark-results) reports
1.53×–12.97× training-loop speedups across 11 cases, with 2.41× for terrain plus
recording. All 66 original/native samples have matching complete-state hashes
within their case. Peak RSS does not consistently fall; QR-DQN rises from 26.3
to 30.6 MiB in the median sample. Local ARM64 Mac/CPython 3.9.6 results are not
universal speed or memory guarantees.

Final checks: **385 Python tests passed under each backend; 50 JS viewer tests
passed**. Native/Python binary replays match across chunk boundaries, and
Markdown links/diagram exports pass validation. Native and
reference tests also cover output ranges, backpropagation, momentum/clipping,
backend switches during resumed episodes, malformed buffers/dimensions,
legacy precision and missing-extension behavior. Timing is measured separately
from tests, without a profiler or concurrent benchmark workers.

## Compatibility and rollback

Checkpoint, model, configuration, replay and viewer formats remain unchanged.
Backend selection is not serialized into learned state. Native/Python checkpoints
can be interchanged on the verified machine/interpreter. Cross-platform numerical
identity is not guaranteed merely by using double arithmetic.

Set `WTF_KERNELS=python` and start a new process to disable acceleration; removing
the ignored extension has the same effect in auto mode. Existing running
processes keep their imported backend until restarted. Viewer/server restart is
not required by this rollout because readers and replay data contracts did not
change. Retain rollout 42's updated readers for its narrower binary arrays.
