## Changes

Explicit setuptools packaging builds a portable wheel and source archive with
MIT metadata and a standalone package-index README. The package includes an
allowlisted 27 presets, seven maps, 22 viewer files and the configuration schema.
Host compiled binaries, local experiments, weights, caches and paper files are
excluded. Native compilation is opt-in for supported CPython versions rather
than a requirement for installation.

`wtf run`, `wtf view`, `wtf analyze`, `wtf presets`, direct aliases and
`python -m ecosystem` expose the existing CLI capabilities after installation.
`load_config` accepts preset names, historical preset paths or local JSONs;
`Experiment` is a lazy top-level export. Runtime assets use importlib.resources
with a source-checkout fallback. Relative results and shared-library paths now
belong to the working directory, avoiding writes into installed package folders.
Relative external map files prefer the working directory before bundled assets.

The world/action extension guide explicitly distinguishes configurable map
symbols/action subsets from new physics/action implementations, complementing
the species/policy handbook. It includes masks, costs, native fallbacks,
signatures, recording, analysis and viewer integration. New shipped resources
must enter the packaging manifest as well as the documentation.

## Compatibility and verification

No publication or container execution is performed. Package version remains the
previously declared `0.1.0`; four-component rollout versions are separate.
Artifacts and model signatures retain their existing formats. Refresh installed
viewer assets by upgrading the package; existing recordings need no conversion.

The isolated installation check uses a clean venv and working directory outside
the checkout, with isolated Python import mode. It validates installed console
commands, all presets, a five-step recorded run, checkpoint restore, diagnostics,
viewer assets/catalog/chunks and rejected static traversal. Wheel and source
archive installations are checked separately. Full source tests and metadata/
file-list checks cover regressions and distribution contents.

Ubuntu CI is configured for Python 3.9, 3.11 and 3.13 portable installations and
an opt-in native 3.11 build. These jobs have not executed locally: macOS
installation results and a Linux code-path review are not an Ubuntu pass.
See the packaging/Linux guides for precise commands and remaining platform checks.

## Verified preparation results

On macOS/CPython 3.9, the portable wheel, source archive and opt-in native wheel
all pass fresh-environment installation checks outside the checkout. Each loads
all 27 presets, completes the short recorded run, restores the checkpoint and
serves the viewer/catalog/chunk endpoints. Twine metadata checks pass for all
three artifacts. The portable wheel includes all 57 allowlisted assets and no
host binary; distribution checks also verify case-sensitive viewer import names,
MIT metadata and exclusion of experiments/caches/development trees.

All 532 Python tests and 99 JavaScript tests pass. Black (118 Python),
clang-format (4 native), Prettier (78 web/config plus workflow/Compose YAML) and
shfmt (2 shell) format/check modes pass. Configuration reference, viewer SVG,
local documentation link and whitespace checks pass. Native compiler selection
is shared between package and checkout builds; a Linux guard test confirms the
macOS discovery path is not entered on Linux. Actual Ubuntu execution remains
pending the configured CI jobs. No Docker or publishing command was run.
