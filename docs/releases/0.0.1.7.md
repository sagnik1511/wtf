## Overview

A wider sight radius previously exposed only one nearest target per category.
Brains can now receive multiple distance-ordered visible targets, giving them
information about alternatives rather than discarding every second target.

## Changes

- Shared brain-template field `observation_top_k`: integer 1–16, default 1.
  Python validation and all nine JSON-schema algorithm branches accept it.
- Fixed slots for k visible food patches, k resource eaters and k prey eaters.
  Each slot has relative x/y, distance and presence; missing slots are zero-padded.
- Selection excludes self, respects occlusion and directional water limits,
  preserves insertion-order distance ties and reuses dynamic spatial indexes.
- Input width is the original version width plus `12 * (k - 1)`. All nine
  algorithms use that sizing, including private newborn brains and GRPO trials.
  Version-3 mate inputs retain their existing summary behavior.
- Nondefault k is recorded in model signatures. Old nearest-only signatures
  remain exact for omitted k or explicit k=1.
- Enhanced river preset opts both species into k=4: 68 terrain inputs each.
  Other presets retain their original k=1 behavior. See the
  [preset guide](../geography.md#river-crossing-with-stronger-predator-capacity).

## Compatibility and migration

Existing checkpoints/configurations default to k=1. Changing k requires fresh
weights or matching-k models for the affected species, including the enhanced
river preset's prey. No weight padding or silent reinterpretation is performed.
There are no new packages or replay format changes. FP64 arithmetic and existing
FP32 weight storage remain. Higher k adds observation/model work; improved
learning outcomes have not been established by long training.

## Validation

- Eight focused top-k tests cover full-scan reference parity, distance ties,
  presence/padding, self exclusion, stationary observers with dynamic targets,
  food/wall changes, directional water sight, changing k/range settings and
  incompatible warm starts.
- All nine algorithms run mixed-k version-1/2/3 observations through learning,
  exact checkpoint continuation and episode chaining. Separate forced-birth
  checks cover independent newborn models and binary/XZ checkpoint continuation
  for all algorithms.
- Enhanced river smoke recording traverses multiple binary/XZ chunks and leaves
  the complete training state identical to an unrecorded run.
- Full Python regression suite: 417 tests passed (seven HTTP socket cases
  excluded because the sandbox blocks localhost binding).
- All 50 JavaScript viewer tests passed.

## Rollout and rollback notes

Committed in `91697aa` on 2026-11-19. Keep the saved configuration
with top-k checkpoints. To return new experiments to nearest-only observations,
set k=1 and use fresh or compatible nearest-only weights. Existing k>1
checkpoints require this reader/runtime; reverting just the input field on their
weights cannot preserve exact continuation.
