## Overview

Reproduction can begin at different ages for animals in the same cohort instead
of every animal crossing the same age and cooldown thresholds. A configurable
inclusive window randomizes each individual's first eligible age and subsequent
cooldowns while retaining the existing health, energy, space and population gates.

## Changes

- Adds optional `age_deviation_pct` and `cooldown_deviation_pct` fields under
  each species' reproduction configuration, with strict numeric validation (0–100) and
  editor-schema support.
- Derives each step deviation from its center times the configured percentage,
  rounding half steps up. Supports fractional percentages; `10` means ±10%.
- Samples a first eligible age once from `[min_age_steps - deviation,
  min_age_steps + deviation]`. Samples a cooldown once after each successful
  birth from the corresponding cooldown window. Intervals are clipped to a
  minimum of one step. Sampling uses the checkpointed world RNG.
- Keeps a blocked animal eligible after its sampled age, including beyond the
  upper edge. A failed birth neither charges energy nor redraws the timer.
  Each newborn starts with an independent unscheduled first-age clock.
- Enables approximately 10% timing deviation in all 16 supplied presets:
  prey first age 270–330 and cooldown 202–248; predator first age 90–110 and
  cooldown 180–220. Health thresholds and reproduction costs/caps are unchanged.
- Stores `reproduction_due_age` with animal state, appends it to delta replay
  field tables and displays scheduled eligibility in the inspector.
- Updates the [configuration guide](../configuration.md#reproduction) and
  reconciles rollout `0.0.0.21` with its existing commit.

## Compatibility and migration

Omitted or zero deviations retain the original fixed rules and consume no extra
RNG draws. Current code restores older checkpoints that lack the new animal
field, and continues their saved zero-deviation configuration. Existing saved
results and brains are not rewritten; JSON preset changes apply to new runs.

Older absolute-step deviation fields remain supported for saved configurations.
New presets use percentage fields; specifying both units for the same clock is
rejected. Changing a center now automatically scales its percentage window.

New pending clocks and RNG state survive exact plain/compact checkpoint resume.
Champion weights do not carry an animal's reproduction schedule into a new run.
Delta readers use each chunk's field table, so old and new recordings remain
readable with the current viewer without changing the replay codec identifier.
Older simulation code may reject the additional animal field in new checkpoints;
preserve the matching code and data when rolling back.

With nonzero age deviation, `min_age_steps` names the window center rather than
a hard lower bound. This feature randomizes eligibility onset; it does not limit
fertility to a temporary window and adds no per-step birth chance. No new package,
brain-signature change or Python package-version increment is required.

## Validation

Passed **241 Python tests** and **31 JavaScript tests**, plus viewer module syntax
and local documentation/preset checks. New tests cover inclusive endpoints,
per-animal spread, clipping, percentage scaling/rounding, legacy-unit
compatibility, ambiguous-unit rejection, draw-once semantics, delayed health/energy/space/cap
conditions, actual-birth cooldown origins, newborn independence, legacy clock
restoration, zero-deviation RNG equivalence and exact JSON/compact continuation
with delta replay round trips. No speed or population-balance improvement is
claimed from these checks.

## Rollout and rollback notes

Start a new experiment using the updated preset. Set both deviation fields to
zero for fixed timing, or omit them in a custom configuration. Existing running
processes retain their loaded rules. Preserve recordings and checkpoints before
switching code revisions; changing a JSON preset does not retune an exact resume.
