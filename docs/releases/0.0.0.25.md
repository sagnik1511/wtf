## Overview

Extends the optimization review to the simulation engine rather than storage.
Simple bounded in-memory dictionaries reuse obstacle-only visibility results
and avoid copying models for champion candidates that lose later in the same
selection pass. Population and reproduction work also avoid repeated per-species
scans/settings checks.

## Changes

- Adds a per-world `OrderedDict` LRU with at most 2,048 ordered endpoint pairs.
  Observation setup clears geometry results on obstacle or visibility-function
  changes. Moving targets still use current spatial-index revisions; direct
  visibility calls remain current and uncached.
- Resolves final champions before taking detached model snapshots. One transient
  model dictionary serves all winning criteria for the same animal in that pass.
  Intermediate record breakers no longer trigger discarded copies.
- Counts populations once per metrics call, including configured empty species,
  and resolves reproduction timing-window flags once per species per phase.
- Documents [simulation cache rules](../performance.md#simulation-caches-and-champion-selection)
  and reconciles the preceding storage rollout with its actual commit.

## Compatibility and migration

No packages, configuration fields, rewards, physics, model dimensions, training
schedules, recording cadence, checkpoint or replay formats change. The visibility
cache is derived, bounded, excluded from persistence and rebuilt on restore.
There is no global LRU retaining old worlds. Its RAM use is a bounded CPU/memory
tradeoff, not a measured memory reduction.

Model snapshots are cached only within one selection pass. Learned predictions
and parameter copies are not memoized across training updates, so weight and
recurrent-memory changes remain visible. Existing mutable-world test/inspection
workflows still reconcile positions, food, obstacles and configuration per phase.
The binary viewer/storage behavior remains the preceding rollout's behavior.

## Validation

Passed **274 Python tests**, including nine new simulation-cache regressions.
279 exact full-state comparisons across all nine algorithms matched the previous
simulation/champion paths over two 15-step episodes per case plus a completed
lifecycle check. They include reproduction windows, forced death, obstacle edits,
checkpoint restoration and champion chaining.

Tests check ray-cache hits and bounded eviction, current target selection after
food removal, obstacle invalidation, absence from saved state, current population
counts, once-per-species timing flags and champion ranks/models against the
former intermediate-copy implementation. A fixture with 40 ascending record
breakers takes one final model snapshot instead of 40 discarded/intermediate
snapshots. No profiler or timing benchmark was used; no overall speedup percentage
or RAM reduction is claimed.

## Rollout and rollback notes

Start a new training process to adopt the optimized engine. Existing brains,
checkpoints and recordings need no conversion. The cache is per world and is
released with that world. Reverting these source changes restores the previous
computation paths without rewriting saved results.
