## Overview

The `dqn` and `ddqn` template types support one to four hidden dense layers.
DQN maximizes target-network values; DDQN selects the next action online and
evaluates that action with the target network. Existing single-layer `q_network` configurations,
presets, arithmetic and saved artifacts remain unchanged.

## Changes and compatibility

Use the [complete DQN template](../algorithms.md#multilayer-dqn). Each controller
owns bounded replay, an independent target network, epsilon-greedy exploration,
Huber TD loss and Adam state. Termination removes bootstrapping; time-limit
truncation preserves it. The implementation reuses the existing packed network,
native arithmetic, value-controller persistence and diagnostic paths without
using QR-DQN's quantile objective. DDQN evaluates only the selected target head.

Dispatch, schema validation, GRPO trial peers, birth/mutation, checkpoint restore,
model warm starts and archived-weight explanations recognize the new type. The
viewer receives scalar Q-values and the actual hidden-layer activation samples.
Models require matching algorithm, architecture, input and action signatures.
No package-version change, preset promotion or publication is included.

## Fixes and optimizations

Independent review verified scalar max-target DQN and online-selection/target-evaluation
DDQN, deep-network persistence, target synchronization, private replay/RNG state,
birth/mutation reset, warm starts, archived explanations and GRPO peer isolation.
Corrected the viewer's algorithm labels so DQN and Double DQN remain distinguishable
in recorded diagnostics. Changed-file Pylint and focused Python/viewer checks pass.
Existing native dense, backpropagation and Adam paths are reused; no additional
optimization or measured speed improvement is claimed.
