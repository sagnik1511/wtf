## Overview

The analyzed 100-episode meandering-river experiment increasingly stopped
hunting and reproducing. Unqualified lineage fallbacks could overwrite qualified
brains, and observations omitted mating eligibility. This rollout guards that
promotion, adds local mating inputs and lengthens/increases GRPO trials in the
meandering preset. Long-term ecological improvement remains unverified.

## Changes

- Fresh experiments default to guarded lineage chaining. An unqualified fallback
  cannot replace a previously qualified matching-species/sex starting brain.
  Retention keeps its model generation and records the skipped promotion in
  provenance. `experiment.guard_lineage_chaining: false` disables this safeguard.
- Optional observation version 3 has 42 inputs: the previous 32, plus sex,
  maturity, cooldown, self readiness, nearest visible opposite-sex same-species
  mate location/readiness and a local pair opportunity signal.
- Mask and observation eligibility share a read-only timing helper. Sight honors
  water-direction bonuses and walls. Phase-local spatial buckets and readiness
  counters avoid recursive/full-world searches per observer; dynamic status is
  rebuilt rather than cached solely by grid position. Observation does not draw
  RNG values, sample maturity windows or imply mating consent.
- Meandering river opts into version 3 and changes predator GRPO horizon 4→16
  and interval 128→32, retaining one group update per step. Other presets keep
  their observation versions and learning cadence. Rewards and physics stay the
  same. More trial work can increase runtime; no speed benchmark is claimed.

## Compatibility and migration

Versions 1/2 retain their 20/32-input contracts. All nine algorithms can explicitly
use version 3 on flat (zero terrain padding) or terrain worlds. Old 20/32-input
weights fail signature checks against 42-input models: start the updated
meandering preset fresh, or provide compatible version-3 weights.

Existing replay formats/viewer controls are unchanged; diagnostics carry the
new array length. New checkpoints/CLI manifests record the effective promotion
guard. Legacy checkpoints without a saved/configured flag retain unguarded
promotion and their embedded observation/trial settings on resume. No packages,
native rebuild, commit, tag or package-version change is required.

## Validation

All **407 Python tests** passed, excluding seven localhost socket tests blocked
by sandbox restrictions. All **50 JavaScript viewer tests** passed. The **11 new
guard/readiness tests** also passed with `WTF_KERNELS=python`. They cover multi-run
retention and opt-out, checkpoint persistence, loaded artifacts/sex isolation,
dynamic readiness/cooldowns, visible mates/walls/water bonus, legacy vectors and
signature rejection, all nine algorithms on flat/water maps with births and
exact continuation, and isolated 16-step GRPO trials with 42-input observations.

A four-frame version-3 binary recording matched JavaScript decoding exactly,
including 42-feature diagnostics. Black/whitespace checks passed and 205 local
documentation links resolved. These are correctness checks, not a completed
long-training or performance benchmark.

## Rollback notes

Disable the guard independently through JSON. To return to 32-input meandering
models, explicitly restore observation version 2 and the previous trial settings
for a new run; do not reinterpret 42-input weights as old models. Existing
recordings retain embedded geography/configuration. Rollouts 1.2/1.3 are
reconciled with the verified user commit `47d8d54`.
