## Behavior

Replaces single-parent births with physically eligible same-species male/female
pairs. Both parents must pass existing maturity, strict health, energy and cooldown
checks, be within an unobstructed configurable radius, and have a free child cell.
Each participates at most once per step. Successful births charge each parent the
full energy cost and start both cooldowns; blocked births charge neither.
A lone survivor cannot reproduce. No mating action or weight-similarity gate. Preset per-parent costs are reduced
from 20 to 10 for prey and 30 to 15 for predators. With unchanged minimum breeding
energies of 30/40, parents retain at least 20/25 energy immediately after birth.
Reproduction does not directly reduce health; starvation can subsequently do so.

Fresh founders use two sex-specific weight initialization seeds with balanced
sex counts; an odd population has one extra female. Founder sex assignments use
the configured seed separately from layout randomness and remain stable between
runs. Controllers are always private. Species/sex-specific champion saving, warm starts and chaining are covered in
the following rollout, [0.0.0.31](0.0.0.31.md).

Uniform scalar crossover mixes both parents' policy/value weights and biases
after current-step feedback. Child temporal/optimizer state starts fresh,
target/reference models synchronize, and rare matrix-only birth mutation remains
unchanged. Crossover can disrupt learned features and is experimental. GRPO
trial births also get independent mixed controllers without altering real agents.

## Configuration, storage and viewer

- All presets expose `reproduction.mate_radius: 2`; omitted values default to 2.
  Valid radius is an integer from 1 to 10, using Euclidean distance and obstacle
  line of sight. [Reproduction guide](../configuration.md#reproduction).
- Bodies store `sex`, maternal `parent_id`, paternal `second_parent_id` and a
  generation one above the maximum parental generation. Newborn sex is 50/50.
- Birth events retain maternal `actor` and child `target`, adding paternal `mate`.
  Delta field tables include body additions; the existing binary format supports
  them without loading entire runs. Inspector/banner display both parents.
- Adds sex-aware body colors and ♀/♂ legend keys; rollout 31 increases the
  color contrast and adds male outlines. Legacy bodies without sex retain base colors;
  species charts and event colors retain their existing meanings.
- Champion source metadata retains sex and both parents. Mutation lineage count
  is maximum parental depth plus a new mutation, not summed unique ancestry.
- Analyzer charges two parental costs for paired events and one for old events.

## Compatibility and adoption

No dependencies, observation-size or action-output changes. Lower preset costs
apply to new experiments; resuming uses costs saved in the checkpoint. Existing champion
signatures stay compatible and old recordings remain viewable. New runs change
initialization and physical outcomes. Old checkpoints remain loadable: missing
sexes use deterministic ID parity and one-template founder banks migrate to both
sexes. Resuming uses paired births and does **not** reproduce the old asexual
numerical trajectory. New JSON/binary checkpoints continue exactly under this
implementation. Restart training processes to adopt the new rules.

- All 39 JavaScript tests pass, including paired birth-marker carry, legacy
  events, run selection, chunk seeking and binary replay decoding.

  infertility and legacy checkpoint migration have direct regression coverage.
- After reducing preset birth costs, all 39 reproduction/genetics/mutation
  tests pass. Direct threshold births for all 32 preset/species combinations
  retain the expected 20/25 energy reserves without changing parent health.
- Presets/schema validate; viewer module syntax, documentation links and diff
  whitespace checked. No performance improvement or learning-quality claim.

## Rollback

Preserve configurations, checkpoints and results before reverting. Older code
may reject new animal/event fields or the sex-specific founder-template bank;
use the reader from this rollout for these checkpoints. Reverting only guides
is independent of simulation data. No commits or tags are created here.
