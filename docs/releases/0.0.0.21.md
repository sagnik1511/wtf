## Overview

Extends the independent-animal trainer with memory, distributional values,
explicit action availability and centralized training context. Each addition has
an environment preset and participates in existing reproduction, saved champions,
recorded playback and exact checkpoint workflows.

## Changes

- `recurrent_ppo`: GRU before a policy/value MLP, clipped PPO updates over
  contiguous truncated-backpropagation sequences, and per-animal hidden state.
  Newborn and warm-start memory is zero; exact resumes retain it.
- `qrdqn`: quantile-regression Double DQN with pairwise quantile Huber loss,
  Adam, bounded replay and a periodically updated target network.
- `maskable_ppo`: normalized probabilities over immediate available actions;
  each PPO sample retains its original mask. Rest or turning is required as
  an available fallback. Masks also apply to evaluation and random baselines.
- `mappo`: experimental centralized-critic PPO with independent per-animal
  actors/critics and mean species rewards. Actors keep local observations;
  critics additionally receive fixed-size team-relative world summaries.
- Adds strict Python/schema validation, architecture-aware model signatures,
  checkpoint restore dispatch, context refresh and GRPO trial support.
- Adds four presets, all using lifespan champions for both species. Existing
  presets retain their algorithm and reward/action semantics.
- Extends viewer labels and diagnostics for masks, recurrent memory, quantile
  values and the species reward scope without coupling rendering to training.
- Adds the [advanced algorithms guide](../advanced-algorithms.md) and reconciles
  the preceding rollout with its actual commit.

## Compatibility and migration

No new packages or package-version changes are required. Existing configurations,
plain/compact checkpoints and recordings retain their interfaces. Readers from
before this rollout cannot execute checkpoints containing the new algorithms.
The replay container remains unchanged; older viewers may mislabel new algorithms.

New models require matching algorithms, actions and architectures; signatures
also identify GRU size, quantile count, separate critic layers and mask/context
versions. Ordinary PPO weights cannot initialize the variants. Champion archives
store parameters; exact checkpoints additionally store memory, replay/rollouts,
optimizer state and random streams. Births copy learned state without copying
experience buffers or recurrent episodic memory.

MAPPO here is a project-specific CTDE variant with independent parameters,
aggregated global critic input and species-mean rewards, not a reproduction of
the original benchmark code. Masking supplies immediate-neighborhood availability
and rules out anticipatory attacks on animals moving into range in the same
step. These variants change the training problem; outcome comparisons must
account for reward scope and masks as well as network size and seeds.

## Validation

Finite-difference tests cover quantile Huber gradients, masked policy/entropy
losses and GRU backpropagation through two timesteps. Lifecycle tests cover
information separation, bootstrap boundaries, newborn memory, stored masks,
reproduction/death, mixed policies, exact JSON/compact continuation, frozen
evaluation parameters, GRPO trial isolation, recording transparency and CLI
progress/champion/warm-start workflows. Verification passed: **229 Python tests**
and **31 JavaScript tests**, plus viewer module syntax, preset/schema field
checks, local documentation links and Git diff whitespace. No learning-quality
or execution-speed improvement is claimed.

## Rollout and rollback notes

Choose a new preset using the commands in the advanced algorithms guide. Start
new training/viewer processes to load the new implementation. Preserve new-format
algorithm checkpoints and compatible champion archives before rolling back; use
the corresponding newer reader to continue them. Existing older-algorithm
experiments can still be run using their original environment files.

Keep this rollout Pending until the implementation is committed, then record
its actual hash/date here and in the hub. This rollout creates no Git tag and
