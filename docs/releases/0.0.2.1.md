## Behavior

Animals can choose a new `challenge` action against a same-species neighbour
nearby when optional competition is enabled. Aggression requires no food or
path objective and grants neither feeding nor displacement priority. A resource-food winner gets the
first normal bite; a winning challenger against a blocker can advance only when
a safe retreat exists or the blocker dies. Damage and attempt costs are
configurable. Existing presets remain disabled; `competition.json` is the
explicit opt-in example.

Contests resolve once per participant per step after movement/drift and before
feeding. Strength uses normalized health plus energy, with seeded ties. Dry
terrain, climb limits, occupancy and effort still constrain displacement.
Competition damage/deaths do not grant predation kill credit or kill energy.

## Integration

- All nine policy implementations accept the action; maskable PPO checks physical
  opportunity without inspecting future opponent choices.
- Existing damage/energy/failure feedback applies. Attempts, resolved choices,
  winners, losers and explicit displacement/death positions enter replay events.
- Analysis/telemetry separate contests and their energy demand from hunting and
  ordinary feeding attempts. The viewer shows bounded amber participant rings, connecting lines, winner/
  damage labels and a contest banner, and distinguishes competition deaths.
  A theme-aware spatial diagram explains the three contest contexts.
- Configuration/schema, packaged presets, customization/physics guides and
  documentation navigation include the opt-in feature.

## Compatibility

No new replay envelope or per-animal checkpoint field is needed. Adding the
ordered action changes the model signature: use fresh or matching weights.
Exact checkpoints restore saved rules and RNG state. Updated readers/viewer
assets are required for new contest semantics; restart the playback server.
The package version remains `0.0.2.0` until a separately requested publication.

## Validation

Controlled tests cover food priority, safe/blocked retreat, lethal contests,
rewards, decision-time masks, codec round trips and exact continuation through
all nine controllers. Aggression-only tests cover side/rear neighbours, damage
without displacement and no resource objective. Validation completed:

- Full Python suite: 580 tests, 22 skipped; all executed tests passed.
- JavaScript suite: 107 passed, including transient contest retention, legacy
  frames and repainting paused playback after theme changes.
- All 16 dedicated mechanics tests passed with both Python and native backends.
- All 35 pre-existing presets produced identical checkpoint/reward/RNG trace
  hashes across 45 controlled steps per preset on both backends.
- Browser inspection verified aggression markers, readable winner/damage labels
  and the banner in light and dark interface themes.
- Whole-source Black, clang-format, Prettier and shfmt formatting/checks passed.
- Documentation/source tooling: 27 tests passed. The site audit checked 1,310
  HTML pages with zero broken links/assets/anchors; all 800 guide/source pages
  were reachable from home. Content-click routes cover 251 public guide pages,
  97 maintained visual files and eight runtime branding copies.

These checks establish mechanics and compatibility, not improved ecological
stability or a universally calibrated competition configuration.

## Rollback

Use presets without competition. For continued use of saved action-compatible
models, disable the feature while retaining the action vocabulary; challenge
choices then have no contest effect and receive ordinary failure feedback.
Preserve any new recordings/checkpoints before reverting reader support.
