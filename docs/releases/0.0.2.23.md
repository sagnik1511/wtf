## Overview

Scalar DQN/DDQN minibatches reduce Python orchestration through an optional native
kernel. Scent observations reuse bounded terrain geometry and phase-local cell
strengths, while social observation/transition phases reuse validated buckets.

## Changes and compatibility

See the [implementation and benchmark guide](../performance.md#scalar-dqn-batches-and-shared-sensory-work)
for cache ownership, bounds, invalidation and numerical safeguards. Private
brains, sampled order, epsilon/RNG state, Adam/clipping, target timing, observations,
physical rules and recorded values retain their contracts. No configuration,
precision, model/checkpoint/replay format or viewer change is required. All
playbacks remain retained according to the existing recording configuration.

Missing/stale native extensions, legacy FP64 models and custom hooks retain the
reference update. Rebuild the optional extension and restart training to enable
`dqn_batch`; no compilation happens at import. Reverting source can use the same
artifact readers. Package version and publication are unchanged.

## Fixes and optimizations

Independent review found no actionable defects requiring an additional fix.
The optional native scalar minibatch preserves sampled transition order, private
model/RNG ownership, target selection, gradient arithmetic and target-update timing;
legacy and custom-hook paths retain the reference implementation. Regression
checks verify exact continuation, late-invalid-sample gradient safety, sensory
cache invalidation, bounded cache ownership and fresh observation values.

Matched five-process local measurements support DQN/DDQN update speedups of
1.19×/1.17×, scent sampling at 3.54× and unchanged social preparation at 1.06×;
complete short recording/recovery workflows improve 1.04×/1.03×. Complete state,
expanded replay and compressed binary artifact hashes match, with unchanged
retained artifact sizes. Allocation/cache tradeoffs are documented; no RAM saving
is claimed. See the [performance guide](../performance.md#scalar-dqn-batches-and-shared-sensory-work)
for workload limits. The decision-batching candidate was not adopted because its
measured benefit was negligible and temporary allocations increased.

## Validation

Five alternating fresh-process samples against the pre-optimization working tree
on `22268d3`, with existing native kernels on both sides, measured DQN/DDQN
updates at 1.19×/1.17×, scent sampling at 3.54× and unchanged social preparations
at 1.06×. Complete 32-step training/recording/recovery workflows improved
1.04×/1.03×. Exact checkpoint/state, expanded replay and compressed binary
artifact hashes match. Retained artifact sizes are unchanged; no RAM saving is
claimed. See the performance guide for workloads, memory tradeoffs and limitations.

All 754 Python tests pass (22 optional/dependency skips); all 147 viewer tests
and 27 documentation/source-reference tests pass. Independent review passes 56
focused tests, including all nine new native/cache tests without skips, and
changed-file Pylint 4.1.4. Repository-wide Black, clang-format, Prettier and shfmt
write/check modes, full maintained-source Pylint, portable wheel/sdist builds
and strict Twine metadata checks pass. The optional extension was rebuilt and
tested on local CPython 3.12; the full OS/Python CI matrix was not executed.

The generated configuration reference, documentation build, homepage access
catalog and local links/assets/anchors checks pass. No ecological experiment
or calibration change is included.
