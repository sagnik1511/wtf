## Changes

Daylight explicitly illuminates the ground before animal/resource glyphs are
drawn. Its intensity peaks at midday; the existing night shade remains. Enabled
recordings now show a visibly brighter daytime board while entity/event colors
remain distinct. This presentation change does not alter sunlight physics.

A header button switches the whole viewer between light and dark interface
palettes, including controls, panels, dialogs, inspector graphics, chart axes and the
board grid/terrain. Light-mode animal outlines preserve species/sex recognition;
water arrows and height labels receive contrasting colors.
The preference is stored locally in the browser and tolerates unavailable storage.
The initial default stays dark. Chart canvases redraw on theme changes even when
playback is paused, without requesting replay data or changing the playhead.
The interface preference remains independent of recorded day/night and its opt-in
configuration; switching themes does not illuminate simulated night.

## Compatibility and validation

Refresh the viewer to load updated assets. No configuration migration, new
recording, dependency or Python/native change is needed for this follow-up.
Theme storage adds one browser preference, not replay/checkpoint data. Rendering
uses CSS tokens and reused components; no independent animation loop is added.

JavaScript tests cover preference restoration, repeated toggles, inaccessible
storage, invalid preferences, daylight intensity and inactive cycles. Browser
verification checks the initial button, switching modes and the existing replay
at midday. The source-rendered appearance catalog includes theme palettes and
updated daylight examples. See the release hub for pending rollout status.
