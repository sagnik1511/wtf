## Overview

This compatible internal-performance release increments the third (PATCH)
component and resets ROLLOUT to zero. The implementation uses compiled **C**
extensions; Python remains the simulation orchestrator and JavaScript remains
the viewer. Public behavior, saved formats and simulation results are preserved.

The first extension left GRU loops, objectives, repeated native/Python layer
crossings, spatial queries and replay expansion in Python. New optional kernels
reduce that work while preserving physical results, private learning/RNG state,
recording bytes and existing viewer behavior. The
[detailed report](../native-kernels-v2.md) documents each boundary and benchmark.

## Changes

- Fused dense inference and plain-PPO minibatch gradients use per-call workspace;
  native probabilities/PPO loss, GRU gates/BPTT and quantile loss retain double math.
- Ordered spatial candidate/ray kernels retain cache invalidation and Python's
  exact final `math.hypot`. Derived byte maps stay out of checkpoints.
- Resource and flat-body phase loops preserve Python numeric types and events.
  Terrain-specific body physics retains its existing implementation.
- Replay comparison/cloning, varint/array handling and sparse dashboard groups are
  compiled without changing formats. Decoder object construction remains Python.
- GRPO trials reuse/reset nonfocal RNG objects instead of repeated seed/restore.
- API versioning handles stale extension binaries. Header-aware builds publish
  atomically and can locate installed macOS tools/SDK without failing shims.

## Compatibility and migration

No environment/model architecture, precision, reward, action/learning cadence,
compression or checkpoint/replay schema changed. Existing brains and recordings
remain usable. Rebuild with `.venv/bin/python -m work.build_native`; new training
or playback-server processes use the new backend automatically. Browser JS is
unchanged. Old processes retain their mapped library; `WTF_KERNELS=python`
selects the reference. Builds and raw results remain ignored. No installed ML
framework or C++ dependency was introduced.

## Validation

**393 native-mode tests passed; fallback mode passed 385 with eight v2-only tests
skipped; all 50 JS tests passed.** Exact comparisons include observation/cache
changes, private learning state, terrain, births/mutations, chaining, checkpoint
resume, wire bytes/signed zero/types, playback and dashboard statistics.

Twelve presets/workloads, three alternating processes per version, seed 42,
48 prey + 12 predators and 180 steps compare against the preceding **native**
setup at `baa5101`. All 72 final checkpoints match within their case. Both flat
and terrain recording comparisons have identical compressed chunks. A separate
1,500-step PPO comparison also matches its full checkpoint and all 1,501 frames'
compressed recording bytes.

Median additional gains include PPO 2.22×, recurrent PPO 21.36×, QR-DQN 4.46×,
replay expansion 3.39× and dashboard summaries 1.90×. Raw binary decoding changed
little (1.03×). Peak RSS is not consistently lower: recurrent PPO measured
31.9 → 35.2 MiB. All timings are local workloads with initialization/digest work
excluded; no universal speed or RAM guarantee is implied. The report includes
full tables, limitations and reproducible commands. No profiler was used.

## Rollout and rollback

Set `WTF_KERNELS=python` for a new process to disable native paths. Existing
formats do not require conversion. Retain the normal Python fallback if reverting
compiled files; missing or older binaries fall back for the added API. Reconciles
rollouts 41–43 with verified user commit `baa5101`; no new commit/tag/package-version
change was made by this rollout.
