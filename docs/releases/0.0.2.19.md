## Behavior and compatibility

The optional consequence predictor supports continuous publication (the legacy
default) or publication before the next training episode. Episode mode stages
bounded evidence separately from frozen published estimates. A CLI override
selects timing for fresh enabled experiments; resume follows saved configuration.
Individual learning and local witness inputs keep their cadence. Inspector text
explains why a changing physical context can change bars with a frozen model.

Evaluation/random episode transitions preserve published and staged knowledge,
preventing accidental publication when resuming staged training state. Exact
episode recovery includes both tables in version-2 model state. Continuous state
and aggregate warm-start exports retain version 1; final exports include all
completed outcome windows without rewriting past replay values. Policy input
width and independent ownership are unchanged. Keep current code for v2 recovery;
a compatible v1 export is available for model warm starts.

The repo-local `wtf-reviewer` skill specifies independent, stable-diff review,
verified findings, coordinated safe fixes and owner decisions. It needs no
persistent custom agent, watcher or Git hook. The shared quality helper formats
maintained sources, checks syntax/config parsing and reports missing tools;
semantic tests and review remain separate.

## Fixes and optimizations

- Fixed publication of staged training evidence after switching to evaluation or random mode. Published and staged knowledge remain unchanged across non-training episode boundaries; regression checks cover both modes and later publication after returning to training.
- Fixed incomplete Python syntax validation. Compilation without execution catches invalid statement scope and duplicate parameters, while regression checks confirm that valid module bodies are never executed.
- Episode checkpoints serialize staged tables without copying the shared physical contracts a second time. Regression checks preserve detached rows/contracts, exact recovery and aggregate exports.
- Stationary witnessed subjects reuse their identical endpoint visibility result. Moving subjects retain both checks, including rejection when their starting position is hidden. This removes one visibility query per stationary witnessed subject without retaining a cross-step cache.

- Added CI regression checks that reject unformatted untracked Python and undefined runtime names, preserve failed-gate status, and require a fresh portable wheel plus source archive before strict metadata validation. Narrow inference exceptions remain attached to their guarded subscriptions after Black formatting; explicit mixin contracts preserve each brain's independent optimizer state. No additional performance optimization was measured in this CI update.

Cleaned Python sources and expanded CI to run full Pylint across runtime code,
tests, examples and development tools, including new untracked sources. Removed
unused imports, documented specific intentional exceptions, made subprocess
failure handling explicit, and restored stdlib callback keyword compatibility
with regression coverage. Preserved simulation arithmetic, RNG behavior and
saved-artifact contracts. No performance improvement is claimed for this cleanup.

The cleanup also uses explicit UTF-8 text I/O, meaningful public API docstrings
and ordinary dictionary literals where equivalent. Keyword `dict(..., **data)`
construction remains when changing it would silently replace duplicate-key
errors with overwrites. Deferred imports, exact numeric type checks, intentional
reference duplication and coherent phase boundaries use named, explained
exceptions in their owning scopes. Unnecessary and duplicate directives were
removed. There is no global warning-disable configuration or lint-debt baseline.

The structural reductions above are verified. Existing path-specific timing and allocation measurements, including their variability and workload limitations, are documented in [performance](../performance.md#collective-learning-hotpaths); this review did not repeat timing measurements. No whole-training speedup, learning improvement or disk reduction is claimed.

Targeted verification passed 32 Python tests and six social viewer tests. No additional actionable code defects or unresolved behavior decisions were identified.

The reviewer also requires Pylint on reviewed Python sources, including staged
and untracked changes. Meaningful findings are fixed; justified exceptions use
specific, narrowly scoped suppression comments with a reason. Missing tools,
nonzero exits and inherited findings remain explicit in the handoff. This is a
development workflow change; no runtime dependencies or global warning exclusions
are introduced. See [Pylint review](../development.md#pylint-review).

CI gates package builds on maintained-source Black formatting and full Pylint,
using pinned development tools shared with `work.check_ci`. Reviewers run these
checks and fresh wheel/sdist builds before handoff, plus relevant documentation,
native and isolated-installation checks. New Pylint warnings, including in tests
and development tools, now fail the gate rather than only package errors/fatals.
