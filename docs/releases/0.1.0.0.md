## Overview

The optional C++ core owns complete CPU simulation and learning episodes, removing
per-animal and per-step Python dispatch. It also initializes worlds/controllers
and performs between-episode champion chaining. Python remains the portable
reference, configuration and query API, and artifact reader/writer. The JavaScript
viewer keeps its existing saved-recording behavior.

## Changes

- Port all 14 built-in learners, their private forward/backward/optimizer paths,
  target/reference networks, recurrent memory and isolated GRPO trial worlds.
- Port physical geography, rivers, elevation, day/night, contests, hunting,
  resources, starvation, proximal consenting reproduction and rare child mutation.
- Preserve V1–V7 inputs, visibility, movement history, scent, local witnesses,
  consequence scopes/publication and the supported private PPO auxiliary/late heads.
- Compute sampled predictions, activations, metrics, champions and lineage in
  the native loop; retain each animal's independent weights and RNG streams.
- Add `--engine cpp` and lazy `NativeExperiment` Python access. Native runs
  release the GIL and reject concurrent queries of the same mutable session.
  Detached query copies do not modify native owners.
- Keep progress, retention and replay/checkpoint/brain-save milestones at bounded
  CLI batch boundaries. Existing formats and readers remain unchanged.
- Add explicit C++17 source/wheel builds, installed-package checks and native
  Ubuntu CI configuration for CPython 3.12–3.13.

## Compatibility and migration

The default remains `--engine python`. Build the optional extension before
selecting `cpp`; see the [support matrix](../native-engine.md#supported-execution-contracts).
Current FP32-stored brains keep the existing FP64 arithmetic and ordered
reductions. Supported checkpoints and recordings remain usable by the Python
readers. Python handles explicit detached queries and compatibility imports;
normal native construction and episode chaining do not build Python learners.

CUDA training, custom Python execution hooks and exact legacy FP64-stored
controller continuation require the Python engine. Selecting C++ does not add an
unported external action or learner. No automatic precision conversion, saved-run
conversion or playback deletion is part of this change.

## Fixes and optimizations

- Reject custom Python execution methods before transferring an existing
  experiment into native ownership, including private learner/network methods,
  GRPO group updates, optional auxiliary/late heads, world/social/sensory helpers,
  champion/lineage and stopping helpers, and private world/action/training/trial/seed
  random generators. Exact owner types also reject helper subclasses. These
  checks prevent a native session from silently discarding custom Python behavior.
- Initialize recurrent newborns in GRPO trial worlds from the child's complete
  reset memory. LSTM trials now retain both hidden and cell vectors, preventing
  a newborn from failing on its next recurrent decision; the live world and
  owning controller state remain isolated from trial execution.
- Keep model and optimizer parameters in private FP32 buffers with FP64
  arithmetic. Reuse bounded learner workspaces, observation-phase spatial/body
  views and unchanged champion encodings; packed imports and copy-on-write
  metadata avoid redundant model trees without exposing live arrays to Python.
- Preserve independent policy/training/trial RNGs, inherited child-state resets,
  shared-evidence publication, full checkpoint continuation and sampled XAI.
  Differential checks cover mixed GRPO/PPO/masked-PPO populations across V2–V7,
  including terrain, social evidence and supported optional heads. All 14 built-in
  learners also retain exact import and continuation across training, evaluation
  and random modes. Boundary
  checks cover detached exports, concurrent queries, malformed counters,
  checkpoint ordering and isolated trial worlds.

No additional algorithm or biological-policy changes were adopted during review.
The engine remains experimental and opt-in. Performance and peak-RAM claims are
limited to the complete workflows reported in [performance](../performance.md);
source-level optimizations alone do not establish a speedup. Local validation
uses CPython 3.12 on macOS ARM64; Linux and CPython 3.13 remain separate CI checks,
and CUDA and exact FP64-stored continuation use the Python engine.

## Validation

- Full Python suite: **966 tests, 5 skipped**; viewer/codec/theme suite:
  **195 tests passed**. Localhost-dependent checks ran with local-server permission.
- Full Black/Pylint gate passed; Pylint **10.00/10**. Portable wheel/source builds
  and strict Twine metadata checks passed. C/C++/JS/shell formatting passed.
- Fresh native wheel installed outside the checkout in an isolated environment.
  Validated **45 bundled presets**; viewer HTTP assets/catalog/chunks, checkpoint
  restore and all **14 installed native learners** passed smoke/parity checks.
- Independent `wtf-reviewer` verification covered boundary edge cases, private
  ownership, all-learner import/continuation and custom-hook rejection.
- Fifteen final paired workflow cases (30 fresh processes) retained exact
  checkpoint values/file bytes, metrics CSV, replay chunks and work counts.
  Ordinary PPO headless training improved **15.952 → 7.951 s (2.01×)**;
  recorded training **21.377 → 14.591 s (1.47×)**. A separate 256-step terrain/social
  workload improved **7.254 → 4.009 s (1.81×)**. Peak RAM increased; see
  [all measured times, RAM and scope](../performance.md#native-ppo-episode-engine).
- Documentation generation and strict link/access checks passed, including
  **2,005 HTML pages and 150,645 local links/assets/anchors**, with no errors.
  The generated C++ reference uses an unambiguous extension-module initializer
  name, avoiding a phantom Doxygen module link.

Local native validation uses macOS ARM64 and CPython 3.12.9. Linux and CPython
3.13 jobs are configured in CI; that configuration is not a locally executed
pass. No GPU speedup or ecological learning improvement is claimed by this port.

## Rollout and rollback notes

Native execution remains explicit and experimental. Keep `--engine python` for
custom hooks, CUDA and legacy precision. Peak RAM and speed depend on workload;
recorded workflows also pay for the existing artifact pipeline. Returning to
Python requires no artifact conversion. Native binaries are specific to the
interpreter, operating system and architecture. This preparation does not create
a commit, tag or PyPI upload.
