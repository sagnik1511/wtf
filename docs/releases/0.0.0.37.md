## Behavior

Adds optional integer `body.water_vision_bonus` (0–32). Each intervening water
cell on an unoccluded visibility ray adds one cell of sight, capped by the bonus.
Rays without water retain the normal limit. Food and animals use the same rule;
walls still block sight, and observer/target endpoints do not grant credit.
River Q, river PPO and enclosed valleys enable a three-cell maximum for both
species; highlands remains unchanged. No swimming or reproduction rule changed.
See [directional sight](../geography.md#directional-sight-across-water).

Search windows cover the maximum possible radius but filter each target by its
actual allowance. Existing nearest-target ordering remains intact. Normalized
features use the maximum radius when enabled on wet maps. Input dimensions stay
20/32 and model shapes remain compatible; changed values/ranges can change policy
behavior. Old captured configs omit the field and preserve the previous rule.

## Caching and storage

Static ordered water-ray counts use a per-world 2,048-entry LRU. Water geometry
is immutable; target results retain existing bucket invalidation and add the
base/bonus pair to their cache key. Obstacle changes invalidate visibility and
spatial results. Restoring a checkpoint reconstructs caches without RNG changes.
No new frame columns, replay formats, dependencies or model tensors were added.

## Verification

All 367 Python tests and 50 JavaScript tests pass. Eight new cases cover
water-limited/capped directionality, wall occlusion, moving/dead targets and food
depletion with a stationary observer, changed base/bonus with equal total range,
zero/default/dry behavior, bounded cached ray counts, diagonal rays, validation,
water preset defaults and exact PPO continuation through real learning updates.
All 20 configs validate; schema, documentation links and whitespace checked.
No long learning experiment or performance improvement is claimed.

## Adoption and rollback

Start a new invocation to use the selected preset's bonus. Set it to zero or
remove it to recover the old sight rule. Existing checkpoints/recordings keep
their captured configuration. Keep updated strict validators when using configs
containing this field; older validators reject it. Older weights with matching
signatures can load, with the ordinary behavioral effect of changed perception.
No commits, tags or package versions were created.
