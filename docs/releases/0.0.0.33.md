## Behavior

Adds three opt-in Q environments and editable ASCII-in-JSON maps: river crossing,
highlands and enclosed valleys. A fourth preset, `river_crossing_ppo.json`, uses
the same river geometry and physical settings with PPO for both species. Existing presets receive no terrain or population
changes. New presets retain one prey species and one predator species. The
[geography guide](../geography.md) describes map syntax and species locomotion.

Normal walking cannot enter or leave water. A swim stroke moves forward only
when in/facing water and requires depth-adjusted health and energy. Currents
advect all animals in water using fractional x/y carry and intermediate-cell
collision checks, preserving occupancy, wall and diagonal-corner constraints.
Flow stops on shore. Species-specific stroke and water-maintenance costs apply;
weak, exhausted or nonswimming animals can drown. Drowning is a distinct death
cause, and a nonlethal attack does not turn a subsequent drowning/starvation
into a predator kill.

Positive elevation gain spends energy; climbs exceeding a species' limit are
blocked. Ramps permit incremental access. Currents also respect climb limits and
uphill costs. Obstacles provide narrow gates and disconnected pockets. Founders,
resources and newborns occupy dry cells; same-species parents need a dry local
route, preventing mating across rivers, cliffs and sealed wall corners.

## Learning and compatibility

Flat observation version 1 remains 20 inputs. Terrain templates explicitly select
version 2 with 32 inputs: current water/flow/height plus relative neighbor water
and elevation differences. All nine algorithms, GRUs, masks and MAPPO actors/
critics use the configured size. The three Q presets share input/action/model
signatures so their weights can transfer between maps. Existing 20-input models
are rejected for these new templates rather than padded/truncated. This terrain change alone preserves flat model signatures. The subsequent
[reproduction rollout](0.0.0.34.md) adds an output action to all presets and
therefore changes those signatures.

Maps may be project-relative or absolute references, resolved into embedded
configuration at load time. Checkpoints/replays remain self-contained if map
sources change or disappear. Body state adds fractional drift carry. Events can
record final positions, keeping death/kill animations correct after multi-cell
advection. Older checkpoint readers may reject these new fields; retain this
reader for new saves. Old checkpoints/replays remain readable. No dependencies
or binary codec version changes are required.

## Viewer, storage and metrics

Terrain metadata is retained once per recording, outside frame chunks. The
viewer shades elevations and rivers, shows current arrows and inspector values,
and labels actual diagnostic feature counts. Per-step selectors include swimming,
drift, terrain energy and drowning. Analysis accounts for the costs separately
from walking; terrain CSVs add a drowning column. No whole-run decompression.

Static geography uses sparse read-only lookups. GRPO trials share those lookups
without sharing dynamic bodies, obstacles, RNGs or perception caches. No new
profiling or performance improvement is claimed.

## Adoption and rollback

Start a new invocation using a terrain preset. Restart the playback server to
load the new telemetry fields, then refresh the browser for overlays.
Saved configurations contain map geometry, so editing the source map affects
new experiments only. Use fresh terrain brains first, then compatible terrain
champions for warm starts. Preserve new checkpoints/results with this reader
before reverting: older code lacks swim, 32-input signatures and drift fields.
No commit, package version or tag is created by preparing this rollout.
